issue-first 工作流

这套工作流只有一条主路径。想法先变成一个 issue。大功能升级成路线图。工作落在 sub-issue 上。最后经集成分支合入 main。

  • 集成分支 feature/swiftui-macos
  • 主干 main
  • 真相来源 GitHub 上的 issue 状态

01主流程

入口是一个 issue，不是一个空目录。用户为大功能提一个 issue，工作流在提完之后判断要不要立项。

立项的动作是提升原 issue，不是另建。另建会让两个 issue 指向同一项功能。

一个 sub-issue 必须能在一个会话内做完。一个 sub-issue 对应一条分支和一个 PR。

02分支拓扑

集成分支承接全部短分支。集成分支在阶段收口时一次合入 main。

同一 epic 的 sub-issue 依次合入集成分支。一次一个，不合批。

两个 issue 同时开工时用 git worktree。一个 worktree 一条分支。worktree 让两条分支不争同一个工作目录。

03三条容易记错的规则

  • epic

    原 issue 就是 epic。立项时提升它，不另建。

  • Closes

    Closes #N 只在目标分支是 main 时生效。短分支到集成分支的 PR 写 Refs #N。关闭动作固定在合入集成分支之后，由 agent 手工执行。

  • milestone

    一个 issue 只挂一个 milestone。sub-issue 跟随它的 epic。
