## 1. 战略与商业维度

### 1.1 业务目标

- 验证 Mac 重度用户的日常效率需求。
- 验证跨设备用户是否愿意持续配对和互传。
- 建立每台设备每周至少完成 3 次核心动作的使用习惯。
- 在不建立账号系统的前提下完成增长验证。
- 在 24 周后判断继续增长、收窄产品还是调整方向。

### 1.2 一句话定位

**Covio 是服务 Mac 重度用户和跨设备协作用户的本地效率中枢。**

定位中的三个概念定义如下：

- Mac 重度用户指长时间使用 Mac、SSH、下载任务或多窗口工作的人员。
- 跨设备协作用户指需要在 Mac、手机和 PC 之间移动内容的用户。
- 本地效率中枢指一个入口管理本机状态和局域网设备。

### 1.3 核心价值主张

- 用户从一个顶部挂帘 Hub 查看电源和设备状态。
- 用户在一个位置处理截图、剪切板和临时文件。
- 用户在局域网内把文件、文本和图片发送到已配对设备。
- 用户不需要注册账号。
- 用户不需要把内容上传到云端。
- 用户在 macOS 上保持原生菜单栏和快捷键体验。
- 用户在移动端和 Windows 上使用同一套模块和视觉语言。

### 1.4 差异化

| 差异点 | Covio 做法 | 用户结果 |
| --- | --- | --- |
| macOS 原生连接 | 保留菜单栏、辅助助手、全局快捷键和系统权限模型。 | 睡眠控制和截图工作流保持原生体验。 |
| 顶部挂帘 Hub | 从顶部中央热区打开可收起的页签区域。 | 用户可用一个手势查看主要模块。 |
| 免账号协作 | 使用二维码或 6 位短码完成局域网配对。 | 用户不创建账号。 |
| 本地优先数据 | 内容、剪切板和临时文件留在设备上。 | 用户可控制敏感内容。 |
| 跨平台一致语言 | macOS、iOS、Android 和 Windows 使用同一模块顺序。 | 用户切换平台时不用重新学习。 |
| 可视化反馈 | 使用挂帘、状态变化和传输进度表达结果。 | 用户可理解当前状态和下一步动作。 |

### 1.5 商业模式

- 测试期完全免费。
- 测试期不显示广告。
- 测试期不设置订阅。
- 测试期不设置交易抽成。
- 测试期不设置会员。
- 测试期不设置增值服务。
- 测试期不收付款信息。
- 24 周后单独评估商业模式。
- 本总稿不承诺后续收费方式。

### 1.6 成功指标

| 指标 | 计算公式 | 目标 | 统计周期 | 数据来源 |
| --- | --- | --- | --- | --- |
| 北极星指标 `WAG` | `count(distinct group_key)`。条件为滚动 7 天内至少 1 个 `transfer_result.result=success`。 | 每月增长。 | 滚动 7 天。 | `transfer_result` |
| `MAU` | `count(distinct install_id)`。条件为窗口内至少 1 个 `app_open`。 | 1000 | 滚动 30 天。W24 时点复盘。 | `app_open` |
| 配对设备组 | `count(distinct group_key)`。 | 300 | 从 W1 到 W24 的累计值。 | `pair_completed` |
| W4 设备组留存 | `W4 成功设备组数 / W0 配对设备组数`。 | 30% | W0 配对，W4 检查。 | `pair_completed`、`transfer_result` |
| 首次传输成功率 | `首次成功设备组数 / 有首次结果的设备组数`。用户主动取消不计入分母。 | 90% | W1 到 W24 的累计值。 | `pair_completed`、`transfer_result` |
| 传输成功率 | `成功次数 / (成功次数 + 失败次数)`。用户主动取消不计入分母。 | 99% | 每周和 W1 到 W24 累计值。 | `transfer_result` |
| 崩溃无感会话 | `1 - 有崩溃报告的会话数 / 会话总数`。 | 99.5% | 每月。 | `crash_report` |

### 1.7 OKR

**O1：验证本地跨设备协作价值。**

- KR1：获得 1000 MAU。
- KR2：获得 300 个配对设备组。
- KR3：达到 30% 的 W4 设备组留存。

- KR1：活跃设备组每周完成至少 3 次核心动作。
- KR2：达到 90% 的首次传输成功率。
- KR3：Hub 打开 P95 不超过 150 毫秒。

**O3：保持稳定和隐私可信。**

- KR1：达到 99.5% 的崩溃无感会话。
- KR2：达到 99% 的传输成功率。
- KR3：匿名事件不包含内容、文件名、路径和网络地址。

## 2. 用户与角色维度

### 2.1 目标用户

| 用户 | 优先级 | 主要需求 | 典型场景 |
| --- | --- | --- | --- |
| Mac 重度用户 | 首要 | 控制睡眠、处理截图、保存临时内容。 | 下载、渲染、开会、长时间开发。 |
| 跨设备协作用户 | 首要 | 在 Mac、手机和 PC 之间移动内容。 | 手机照片发到 Mac，PC 文件发到手机。 |
| 远程开发人员 | 次要 | 保持 SSH 会话和远端任务运行。 | 合盖后继续连接服务器。 |
| 运维人员 | 次要 | 在设备间传日志、密钥外的配置和截图。 | 排障和交接。 |
| 内容创作者 | 次要 | 收集截图、参考资料和临时素材。 | 跨屏整理素材。 |

### 2.2 用户画像

**画像 A：Mac 重度用户**

- 使用 macOS 12 或更高版本。
- 同时打开多个窗口和浏览器标签。
- 经常下载文件、运行构建或连接远端主机。
- 关注菜单栏状态、快捷键和键盘效率。
- 不希望注册账号。
- 不希望内容离开本机或局域网。

**画像 B：跨设备协作用户**

- 同时使用 Mac、手机和 Windows PC。
- 经常用桌面设备查看手机内容。
- 经常把文件从 PC 发送到 Mac。
- 关注配对速度、传输进度和错误恢复。
- 不希望为一次传输上传文件到云端。

**画像 C：远程开发或运维人员**

- 使用 SSH 连接服务器。
- 需要 Mac 在合盖或闲置时继续工作。
- 需要快速保存截图和日志。
- 需要知道睡眠规则、电池状态和助手状态。

### 2.3 角色与权限

| 角色 | 权限 | 限制 |
| --- | --- | --- |
| 设备所有者 (`Owner`) | 管理本机内容、设置、权限和设备列表。 | 只能管理当前设备。 |
| 已配对设备 (`Paired Device`) | 按设备授权发送文件、文本或图片。 | 不能管理对端设置。 |
| 未配对设备 | 只能发现公开展示的配对邀请。 | 不能读取内容。 |
| 已撤销设备 | 不能连接、传输或同步剪切板。 | 需要重新配对。 |

- 系统不设置云端管理员。
- 系统不设置商家角色。
- 系统不设置团队管理员。
- 系统不设置内容审核员。
- 每台设备的设置由设备所有者管理。
- 每台设备可撤销任意已配对设备。
- 设备撤销立即断开连接。
- 设备撤销删除对端密钥。
- 设备撤销不删除用户主动保存的本地文件。

### 2.4 用户生命周期

| 阶段 | 用户状态 | 产品动作 | 成功条件 |
| --- | --- | --- | --- |
| 新手 | 首次启动。 | 说明本地模式、协作模式和权限。 | 用户完成任一可用入口。 |
| 已配对 | 完成设备配对。 | 引导发送第一个文件或文本。 | 首次传输成功。 |
| 活跃 | 每周使用核心模块。 | 保持状态清晰并提供快捷键。 | 每周至少 3 次核心动作。 |
| 沉默 | 7 天未打开 App。 | 显示本地待处理项或设备通知。 | 用户重新完成一次动作。 |
| 流失 | 30 天未打开 App。 | 不发送促销通知。 | 用户主动返回。 |
| 召回 | 用户主动返回。 | 恢复本地状态并显示待处理项。 | 用户再次完成一次动作。 |

## 3. 需求与场景维度

### 3.1 需求条目

本节按需求域列出产品要做什么。
每个域写四段：要什么、为什么、边界、依据。
「要什么」写需求。「为什么」写用户问题。「边界」写这个域做到哪为止。
需求不带编号。其他文档引用本节时用章节锚点。
「依据」链接支撑该域的调研报告。没有调研支撑的域写「无独立调研」。
本文用「工作区」指模型里的一个页签。界面文案仍可用「页签」。两个词指同一件事。

#### 3.1.1 电源与睡眠控制

**要什么**

- 用户从菜单栏或 Hub 控制睡眠规则。
- 规则覆盖合盖、空闲和电池三种条件。
- 特权助手缺失时，用户可以手动触发睡眠。

**为什么**

Mac 在长时间任务中会睡眠。用户当前要改系统设置，或者保持屏幕常亮。两种做法都打断用户的其他工作。

**边界**

- 不做远程电源控制。
- 不做定时任务调度。
- 不做跨设备的电源规则同步。

**依据**

无独立调研。

#### 3.1.2 截图

**要什么**

- Covio 接管系统截图快捷键。
- 用户捕获后可复制、预览、标记和移动截图。
- 截图保存在本机。
- 用户可以设置截图保留期。

**为什么**

系统截图之后的整理依赖桌面缩略图和 Finder。用户整理多张截图时要反复切换窗口。

**边界**

- 不做屏幕录制。
- 不做截图内容识别。
- 不做云端截图存储。

**依据**

无独立调研。

#### 3.1.3 剪切板

**要什么**

- Covio 保存文本、图片和文件列表。
- 历史保存在本机。用户可以置顶条目。
- 已配对的设备之间同步剪切板。
- 用户可以暂停同步。

**为什么**

用户在设备之间搬运内容时依赖聊天软件或网盘。这些工具要求账号和网络。

**边界**

- 不做云端剪切板存储。
- 不读取密码管理器标记为机密的条目。

**依据**

[跨设备内容读取能力](research/cross-device-content-access/README.md)

#### 3.1.4 临时文件

**要什么**

- 用户把文件拖入 Covio 暂存。
- 用户可以置顶文件。置顶文件不自动清理。
- 文件在过期前显示剩余时间。
- 用户可以设置保留期。

**为什么**

用户在设备之间搬运文件时缺少中转位置。桌面和下载目录会累积临时文件。

**边界**

- 不做文件同步。
- 不做文件版本管理。
- 不做云端暂存。

**依据**

[跨设备共享暂存工作区](research/shared-transfer-workspace/README.md)

#### 3.1.5 局域网互传

**要什么**

- 用户不建账号即可配对设备。
- 配对使用二维码或 6 位短码。
- 传输只走局域网。
- 传输失败后可以重试。队列不丢失。
- 用户可以撤销已配对的设备。

**为什么**

用户在设备之间搬运大文件时依赖网盘或数据线。网盘上传慢。数据线要求物理接触。

**边界**

- 不做跨网中继。
- 不做远程屏幕和远程输入。
- 不做账号体系。

**依据**

[跨设备内容读取能力](research/cross-device-content-access/README.md)

#### 3.1.6 挂帘 Hub 与工作台

**要什么**

- 用户用四类入口打开 Hub：触控板手势、刘海悬停、全局快捷键和菜单栏图标。
- Hub 展开后是层级最高的组合式工作区域。
- 工作区是数据，不是硬编码。
- 默认有六个工作区。首页是 Widgets。
- 用户可以调整工作区顺序。
- 每个工作区支持编辑和设置。
- Windows 用固定区域触发。
- iOS 用交互小组件。iOS 不用主屏手势。

**为什么**

用户要在不切换应用的前提下查看主要模块。菜单栏和 Dock 都要求精确点击。系统不向第三方应用开放 iOS 主屏手势入口。

**边界**

- 工作区数量上限，待 `ADR-006` 决定。
- 内置工作区能否删除，待 `ADR-006` 决定。
- iOS 不做主屏上滑手势。
- 触发层不做跨平台共享实现。

**依据**

[触控板多指手势入口](research/trackpad-gesture-entry/README.md)、[iOS 免打开入口](research/mobile-ambient-entry/README.md)

#### 3.1.7 隐私与本地优先

**要什么**

- 产品不要求账号。
- 内容和文件只保存在本机。
- 文件互传只走局域网。
- 产品不建立云端内容存储。
- 用户发送匿名事件前可见事件内容。
- 用户可以重置本机标识。

**为什么**

用户搬运的内容可能包含工作资料。账号和云端存储会扩大数据暴露范围。

**边界**

- 不做云端内容存储。
- 不做跨网中继。
- 匿名事件不包含内容和文件。

**依据**

无独立调研。

### 3.2 核心任务

| 优先级 | 用户任务 | 当前替代方案 | Covio 结果 |
| --- | --- | --- | --- |
| 1 | 保持 Mac 和远端任务运行。 | 修改系统设置、使用命令行或保持屏幕常亮。 | 用户从菜单栏或 Hub 控制睡眠规则。 |
| 2 | 截取、查看、复制和移动截图。 | 桌面缩略图和 Finder。 | 用户从截图页签处理截图。 |
| 3 | 在设备间移动剪切板和文件。 | 聊天软件、网盘、AirDrop 或数据线。 | 用户在局域网内配对并直接传输。 |

### 3.3 用户旅程

**本地单人流程**

1. 用户安装并打开 Covio。
2. 用户选择本地模式。
3. 用户按需安装特权助手。
4. 用户设置睡眠规则。
5. 用户截取屏幕。
6. 用户从截图页签复制、预览、标记或移动截图。
7. 用户关闭窗口。Covio 继续在菜单栏运行。

**双设备协作流程**

1. 两台设备打开 Covio。
2. 两台设备加入同一局域网。
3. 设备通过 Bonjour 或 mDNS 发现对方。
4. 一台设备生成二维码或 6 位短码。
5. 另一台设备扫描二维码或输入短码。
6. 两台设备显示相同的 6 位确认码。
7. 用户确认两台设备显示的确认码相同。
8. 两台设备交换设备密钥。
9. 用户设置文件、剪切板和自动接收权限。
10. 用户发送第一个文件或文本。
11. 两台设备显示传输进度和结果。

### 3.4 关键触点

| 触点 | 用户问题 | 设计结果 |
| --- | --- | --- |
| 首次启动 | Covio 是否需要账号？ | 明确说明无需账号。 |
| 权限申请 | 为什么需要本地网络权限？ | 说明权限只用于设备发现和传输。 |
| 配对 | 如何确认设备可信？ | 显示二维码、短码和 6 位确认码。 |
| 首次传输 | 文件去了哪里？ | 显示目标设备、进度、大小和保存位置。 |
| 传输失败 | 能否继续？ | 显示原因、重试和保留队列。 |
| 临时文件过期 | 文件何时删除？ | 显示剩余时间和置顶操作。 |
| 设备离线 | 队列是否丢失？ | 保留队列并等待设备上线。 |
| 撤销设备 | 是否删除本地文件？ | 说明只删除密钥和授权。 |

| Should | 工作区编辑器、Widgets 网格布局、每工作区设置、置顶内容、传输暂停、断点续传、设备昵称、传输历史、截图标记、快捷键。 |
| Could | 批量选择、拖放排序、二维码名片、设备分组、自动清理规则、自定义工作区布局。 |
| Won't | 账号、云同步、跨网中继、远程屏幕、远程输入、SSH、支付、广告、社区、积分任务。 |

### 3.6 公开测试版范围

- 公开发布 6 个产品模块。
- 公开测试期默认提供六个工作区。首页是 Widgets。
- 工作区数量上限和内置工作区能否删除，待 `ADR-006` 决定。
- macOS 提供完整模块能力。
- Windows 提供剪切板、临时文件、互传、截图导入和 Hub。
- iOS 提供配对、互传、剪切板、临时文件和截图入口。
- Android 提供配对、互传、剪切板、临时文件和截图入口。
- 所有平台使用同一默认工作区顺序。
- 所有平台使用同一数据授权语言。
- 所有平台不要求账号。
- 所有平台不要求云端内容存储。

### 3.7 待验证假设

- 用户是否愿意长期保留配对关系。
- 用户是否每周使用剪切板同步。
- 用户是否把临时文件当作工作台。
- 用户是否接受顶部挂帘 Hub。
- 动画是否帮助用户理解状态变化。
- 用户是否需要批量传输。
- 用户是否需要跨网传输。
- 用户是否接受匿名事件。
- 用户是否会把 SSH 需求转化为后续付费需求。
- 用户是否把手机截图入口当作高频功能。

### 4.4 顶部挂帘行为

- 用户编辑输入或拖动文件时，Hub 不自动收起。
- 用户按下 `Escape`。Hub 立即收起。
- 用户按下 `Control+Option+T`。Hub 打开或收起。
- 菜单栏图标始终可用。
- Hub 打开失败时，用户仍可从菜单栏进入。
- 全屏 Space 中隐藏顶部热区。
- 刘海屏使用顶部中央区域。
- 非刘海屏使用菜单栏下方的小型透明热区。
- 多显示器使用指针所在屏幕。
- 外部显示器使用与主屏相同的触发规则。

## 5. 流程与交互维度

### 5.1 首次启动流程

1. Covio 显示产品定位。
2. 用户选择本地模式或协作模式。
3. 用户选择协作模式时，Covio 说明本地网络用途。
4. 用户选择本地模式时，Covio 直接进入 `Now`。
5. Covio 请求当前任务需要的权限。
6. Covio 显示 Hub 使用提示。
7. Covio 显示匿名事件说明。
8. 用户完成任一核心动作后，Covio 结束新手状态。

### 5.2 配对流程

1. 用户打开 `Devices`。
2. Covio 开始设备发现。
3. 用户选择目标设备。
4. 发起端显示二维码和 6 位短码。
5. 接收端扫描二维码或输入短码。
6. 两台设备显示相同的 6 位确认码。
7. 用户确认确认码相同。
8. 两台设备交换设备密钥。
9. 两台设备显示配对成功。
10. 用户设置文件、剪切板和自动接收权限。

### 5.3 配对异常流程

- 短码在 120 秒后失效。
- 短码失效后，用户生成新短码。
- 两台设备不在同一局域网时，Covio 显示网络提示。
- 系统阻止本地网络权限时，Covio 显示设置入口。
- 防火墙阻止连接时，Covio 显示防火墙指引。
- 确认码不同时，Covio 立即终止配对。
- 用户取消配对时，Covio 删除临时密钥。
- 配对超时时，Covio 保留发现列表。
- 设备名称冲突时，Covio 要求用户修改昵称。

### 5.4 文件传输流程

1. 用户选择文件或文件夹。
2. 用户选择目标设备。
3. Covio 检查权限和磁盘空间。
4. Covio 创建传输任务。
5. 两台设备显示任务和进度。
6. Covio 分块发送内容。
7. 网络中断时，Covio 暂停任务。
8. 网络恢复后，Covio 继续任务。
9. 接收端完成校验后，Covio 显示成功。
10. 用户可在任务历史中查看结果。

### 5.5 剪切板同步流程

1. 用户在已授权设备上复制文本、图片或文件列表。
2. Covio 读取允许同步的内容类型。
3. Covio 把内容加入本地剪切板历史。
4. Covio 向已授权设备发送同步任务。
5. 对端设备保存内容。
6. 对端设备显示同步结果。
7. 用户可从 Hub 复制或发送历史内容。

### 5.6 临时文件流程

1. 用户把文件拖入 `Files`。
2. Covio 保存文件到本地临时区。
3. Covio 记录创建时间和过期时间。
4. 用户在 30 天内打开、发送或置顶文件。
5. 到期前 72 小时和 24 小时，Covio 显示提醒。
6. 文件到期后，Covio 删除未置顶文件。
7. 置顶文件不自动删除。
8. 空间达到 5 GB 时，Covio 提醒用户清理。

### 5.7 截图流程

1. 用户使用系统截图。
2. Covio 接收截图。
3. 截图进入 `Screenshots`。
4. 用户单击卡片复制图片和文件地址。
5. 用户双击卡片打开预览。
6. 用户长按或选择标记。
7. 用户把卡片拖到应用、文件夹、桌面或废纸篓。
8. 操作失败时，Covio 把卡片放回原位置。

### 5.8 电源流程

1. 用户打开 `Now`。
2. 用户查看电池、电源和合盖状态。
3. 用户切换睡眠规则。
4. Covio 检查特权助手。
5. 助手缺失时，Covio 要求用户安装助手。
6. 设置成功后，Covio 更新状态和工具提示。
7. 用户可运行立即睡眠或关闭显示器。
8. 用户可设置定时取消。

### 5.9 状态设计

| 状态 | 界面行为 | 恢复动作 |
| --- | --- | --- |
| 空 | 显示模块用途和主要动作。 | 用户可以添加内容或配对设备。 |
| 加载 | 显示骨架或进度。 | 用户等待或取消。 |
| 成功 | 显示结果、位置和完成时间。 | 用户可以复制、打开或继续。 |
| 错误 | 显示原因和恢复动作。 | 用户可以重试、修改设置或复制诊断信息。 |
| 离线 | 保留队列并显示设备状态。 | 设备上线后自动恢复。 |
| 无权限 | 说明权限用途。 | 用户可打开系统设置。 |
| 冲突 | 显示两个内容和时间。 | 用户选择保留版本。 |
| 空间不足 | 显示所需空间和可用空间。 | 用户清理内容或更换位置。 |

### 5.10 表单和输入

- 配对短码输入使用 6 个数字位。
- 设备昵称最多 32 个字符。
- 文件搜索支持名称和类型。
- 临时文件保留时间提供 1、7、30 和 90 天选项。
- 空间上限提供 1、5、10 和 20 GB 选项。
- 无效短码显示行内错误。
- 无效昵称保留原值。
- 用户按回车提交短码。
- 用户按 `Escape` 取消输入。
- 提交期间禁用重复提交。

### 5.11 通知

- 配对请求需要用户确认。
- 传输完成显示目标设备和结果。
- 传输失败显示失败原因。
- 临时文件即将过期显示剩余时间。
- 助手状态异常显示安装或更新动作。
- 设备离线不发送高频通知。
- 广告和促销通知永远不发送。
- 用户可按模块关闭通知。

### 5.12 可逆和可恢复

- 删除剪切板条目后提供 5 秒撤销。
- 删除临时文件后提供 5 秒撤销。
- 移除截图卡片后提供 5 秒撤销。
- 取消传输后保留任务记录。
- 失败传输可从断点继续。
- 撤销设备需要二次确认。
- 撤销设备不删除本地文件。
- 清理临时文件前显示数量、大小和置顶例外。
- 退出 App 不删除未完成任务。
- 下次启动时恢复未完成任务。

## 7. 技术与数据维度

### 7.1 平台架构

| 层 | 方案 | 说明 |
| --- | --- | --- |
| 共享领域层 | Kotlin Multiplatform | 保存模型、协议、队列、配对状态和业务规则。 |
| 共享界面层 | Compose Multiplatform | 复用 Windows 和 Android 界面。macOS 界面改用 SwiftUI。 |
| iOS 宿主 | Compose UI 加 Swift 原生桥接 | 接入分享面板、后台任务和系统权限。 |
| Windows 宿主 | Compose Desktop 加原生桥接 | 接入托盘、防火墙提示和文件系统。 |

### 7.2 设备发现和配对

- 使用 Bonjour 或 mDNS 发现同一局域网设备。
- 使用二维码传递设备标识和短期令牌。
- 使用 6 位短码支持手动配对。
- 短码有效期为 120 秒。
- 使用 6 位确认码防止中间设备。
- 使用每设备密钥保存信任关系。
- 使用 TLS 1.3 保护连接。
- 使用端到端加密保护内容。
- 使用前向保密密钥。
- 设备撤销后删除会话密钥。
- 设备列表最多保留 8 台已配对设备。
- 用户可以手动刷新设备发现。

### 7.3 传输协议

- 使用分块传输。
- 使用 SHA-256 校验完整性。
- 使用断点续传恢复大文件。
- 默认允许 3 个并发传输。
- 大文件在局域网中断后保留任务。
- 传输任务显示方向、设备、大小和进度。
- 用户可暂停、继续或取消任务。
- 用户主动取消不计入传输失败率。
- 文件只在用户发送时离开本机。
- 接收文件先写入临时目录。
- 校验成功后移动到目标目录。
- 校验失败时删除不完整文件。

### 7.9 数据埋点

- 匿名产品事件只有 3 类。
- `app_open` 记录启动和留存。
- `pair_completed` 记录配对成功。
- `transfer_result` 记录文件或剪切板传输结果。
- 产品事件只包含随机安装标识、平台、版本和语言。
- `pair_completed` 包含两台设备的随机安装标识。
- 分析服务从随机安装标识计算 `group_key`。
- `group_key` 是派生值。`group_key` 不进入产品事件。
- `transfer_result` 包含方向、字节数区间、耗时、结果和错误分类。
- `crash_report` 是独立诊断数据。`crash_report` 不进入产品事件。
- 产品事件不包含文件内容、文件名和文件路径。
- 产品事件不包含剪切板正文。
- 产品事件不包含设备名称、IP 地址和网络名称。
- 崩溃报告不包含文件内容、文件名和文件路径。
- 崩溃报告不包含剪切板正文。
- 崩溃报告不包含设备名称、IP 地址和网络名称。
- 原始事件保留 90 天。
- 聚合数据可以长期保留。
- 用户可关闭事件采集。
- 用户可重置随机安装标识。
- EEA、英国和瑞士用户先同意，再启用事件。
- 其他地区默认开启事件。
- 首次启动说明采集范围。
- 设置页提供退出入口。

### 7.10 事件定义

**匿名产品事件**

| 事件 | 触发时机 | 主要字段 | 用途 |
| --- | --- | --- | --- |

| 报告 | 触发时机 | 主要字段 | 用途 |
| --- | --- | --- | --- |

## 附录 C：流程状态

### 配对状态

| 状态 | 含义 | 下一状态 |
| --- | --- | --- |
| `UNPAIRED` | 当前设备没有配对关系。 | `DISCOVERING` |
| `DISCOVERING` | 正在发现局域网设备。 | `PAIRING`、`UNPAIRED` |
| `PAIRING` | 正在验证短码和密钥。 | `PAIRED`、`FAILED` |
| `PAIRED` | 设备已授权。 | `OFFLINE`、`REVOKED` |
| `OFFLINE` | 已配对设备当前不可达。 | `PAIRED`、`REVOKED` |
| `REVOKED` | 设备授权已删除。 | `UNPAIRED` |
| `FAILED` | 配对失败。 | `DISCOVERING`、`UNPAIRED` |

### 传输状态

| 状态 | 含义 | 下一状态 |
| --- | --- | --- |
| `QUEUED` | 等待发送或接收。 | `TRANSFERRING`、`CANCELLED` |
| `TRANSFERRING` | 正在传输内容。 | `PAUSED`、`COMPLETED`、`FAILED`、`CANCELLED` |
| `PAUSED` | 用户暂停或网络中断。 | `TRANSFERRING`、`CANCELLED` |
| `COMPLETED` | 文件校验成功。 | 终态 |
| `FAILED` | 传输或校验失败。 | `QUEUED`、`CANCELLED` |
| `CANCELLED` | 用户主动取消。 | `QUEUED`、终态 |
