# 前因与问题边界

> 本文件承载前因、研究问题、问题类别、适用边界、场景和成功标准。

## 1. 问题类别与适用边界

### 1.1 研究问题

macOS 应用能否在全局范围检测“触控板四指下滑”？
如果可以，需要哪个 API 和哪个权限？
如果不可以，降级入口是什么？

### 1.2 问题定义

问题类别是**系统保留手势的再获取**。
一类问题是：操作系统把某个用户手势保留给系统功能，第三方应用能否重新获得该手势。
问题类别不绑定 Covio。任何需要多指手势入口的 macOS 应用都面对同一类问题。

### 1.3 触发条件

1. 应用需要在自身窗口失焦时接收手势。
2. 应用需要的手指数与系统功能的手指数相同。
3. 应用不申请输入监控权限，或者申请被拒。

### 1.4 问题分类

| 类别 | 表现 | 主要因素 | 推荐路径 |
| --- | --- | --- | --- |
| 系统未占用 | 应用能收到公开手势事件 | 系统偏好把该手势设为关闭 | 公开 `NSEvent` 手势事件 |
| 系统已占用 | 应用收不到任何事件 | 系统偏好把该手势绑给系统功能 | 私有多触点设备，或改用手势数不同的入口 |
| 权限被拒 | 监视器注册成功但不回调 | TCC 拒绝输入监控 | 降级到窗口内热区和快捷键 |
| 私有 API 失效 | 调用崩溃或返回空 | 系统版本升级改变私有表面 | 降级到窗口内热区和快捷键 |

### 1.5 状态矩阵

矩阵的行是环境状态，列是三条候选路径的可用性。

| 状态 | 公开 NSEvent 手势 | CGEventTap 滚轮 | 私有 MultitouchSupport |
| --- | --- | --- | --- |
| 系统手势开启（本机默认） | 不可用 | 不可用 | 可用 |
| 系统手势关闭 | 部分可用，只覆盖前台应用 | 可用，但分不出手指数 | 可用 |
| 应用失焦 | 不可用 | 可用，但分不出手指数 | 可用 |
| 输入监控被拒 | 不可用 | 不可用 | 可用 |
| 私有框架缺失 | 不可用 | 可用 | 不可用 |
| 全屏 Space | 不可用 | 可用 | 可用 |
| 合盖外接显示器 | 不可用 | 不可用 | 不可用 |

### 1.6 解决路径

三条候选路径分别对应公开事件、事件流和私有设备。
第 1.5 节显示只有私有路径同时满足“四指”和“应用失焦”。
因此主路径是私有设备。另外两条作为降级和补充。

## 2. 场景定义

### 2.1 场景一：正常触发

用户合盖使用内建触控板。挂帘处于收起状态。
用户四指下滑。挂帘展开。

限制：系统手势必须不占用四指垂直轻扫，或者应用绕过系统手势。

### 2.2 场景二：外接触控板

用户通过蓝牙连接外接触控板。用户四指下滑。
私有 `MTDeviceCreateList` 返回多个设备。应用必须逐个设备注册回调。

限制：外接设备在 `MTDeviceCreateList` 中的顺序不固定。

### 2.3 场景三：外接鼠标，无触控板

用户合盖接显示器，只用鼠标。
手势入口不存在。挂帘只能由悬停、快捷键和菜单栏图标打开。

限制：应用必须能检测“没有可用触控板”，并且不报错。

### 2.4 场景四：私有路径失效

系统升级后私有符号被移除或改变。
应用必须继续启动，并且降级到其余入口。

限制：失效检测必须在启动时完成，不能等到用户做手势。

## 3. 成功标准

1. 四指下滑在应用失焦时能打开挂帘。
2. 手势识别不依赖系统手势偏好。
3. 私有路径失效时应用不崩溃，并且其余入口可用。
4. 应用不申请输入监控权限也能收到四指下滑。
5. 手势的误触发率低于每分钟一次。
6. 手势的响应延迟低于 150 毫秒。
