## 2. 验证目标

验证 [conclusion.md](../conclusion.md) 第 3 节的八个回答是否成立。
验证 [conclusion.md](../conclusion.md) 第 4 节的优先级顺序是否合理。
验证 [solution.md](../solution.md) 第 9 节的验收标准是否可达。
目标分四项。

1. 确认主屏与锁屏手势没有第三方注册入口。
2. 确认小组件、控件和 Action Button 能在应用未启动时触发动作。
3. 确认控制中心控件能打开应用并进入指定工作区。
4. 确认锁定状态和用户未配置状态下的实际行为。

## 3. 范围内事项

1. 主屏交互小组件的按钮与开关。
2. 锁屏交互小组件的按钮与开关。
3. 控制中心控件与锁屏控件。
4. Action Button 绑定 App Shortcut 与控件。
5. 轻点背面绑定快捷指令。
6. 主屏快捷指令书签。
7. 应用内 `presentationDetents` bottom sheet。
8. 锁定状态、未配置状态和低版本状态的降级行为。

## 4. 范围外事项

1. 越狱设备与私有接口。
2. 企业签名与自签分发。
3. 云端中继与账号体系。

5. 长期耗电与性能测量。
6. 全部 iPhone 机型的覆盖。
7. Android 与 Windows 平台的入口。
8. 任何 iOS 实现任务的排期。

## 6. 成功标准

1. 每个测试有明确的通过或失败判定。
2. 失败项保留错误码与原始输出摘要。
3. 每个结论回填到 [evidence.md](../evidence.md)。
4. 与文档冲突的观察写入反证章节。
5. 临时设置与临时入口全部恢复。
6. 每个入口记录可用性、版本门槛、配置成本和冷启动四项。

## 7. 前置条件

1. 一台可安装测试构建的 iPhone 真机。
2. 设备系统版本不低于 iOS 18.0。
3. 一台 iOS 17.0 的设备用于交互小组件测试。
4. 一台 iOS 14 至 iOS 16 的设备用于降级测试。
5. 设备支持 Action Button，或另备一台支持机型。
6. 测试构建带 Widget 扩展目标。
7. 测试构建的 App Intent 已加入主应用与扩展目标。
8. 测试前记录系统版本、机型与构建号。
9. 测试设备上没有正在进行的备份任务。

## 8. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 在真机上添加系统入口 | 用户的真实主屏与锁屏被改变 | 用独立测试设备，测试后移除入口 |
| 修改轻点背面设置 | 覆盖用户已配置的动作 | 记录原值，测试后恢复 |
| 修改 Action Button 设置 | 覆盖用户已配置的功能 | 记录原值，测试后恢复 |
| 锁定设备上触发动作 | 可能泄露工作区名称 | 只用测试工作区，不用真实数据 |
| 卸载重装应用 | 已添加入口的状态丢失 | 单独记录该状态，测试后重建 |
| 共享容器写入测试数据 | 残留数据影响后续测试 | 测试后清空共享容器 |
| 设备升级或降级 | 系统状态被改变 | 不在生产设备上执行降级 |

**警告：** 执行前记录轻点背面与 Action Button 的原配置。测试会覆盖这两项设置。

1. 每个测试记录开始时间与结束时间。

4. 每个测试记录观察到的输出摘要。
