# 前因与问题边界

> 本文件承载前因、研究问题、问题类别、适用边界、场景和成功标准。

## 1. 问题类别与适用边界

### 1.1 研究问题

产品需求要求在 iOS 主页用上滑手势带出 bottom sheet。
iOS 不向第三方应用提供主屏手势入口。
因此需要回答一个替代问题。
替代问题是：iOS 上哪些入口能在不打开应用的前提下触发应用动作。

研究问题拆成三个子问题。

1. 系统手势：主屏手势、锁屏手势和边缘手势对第三方应用是否开放？
2. 系统接入面：WidgetKit、控制中心控件、Action Button 和 App Intent 各提供什么能力？
3. 应用内替代：应用内的 `presentationDetents` bottom sheet 能否替代主屏上滑手感？

### 1.2 问题定义

本文处理一类免打开入口问题。
非系统应用需要在系统空间中暴露一个动作入口。
系统空间包括主屏、锁屏、控制中心、Action Button 和辅助功能手势。
系统只开放部分空间给第三方应用。
每个空间的开放程度、版本门槛和用户配置成本不同。
因此能力边界同时受三条线约束。
三条线是系统空间开放性、系统版本门槛和用户配置成本。

### 1.3 触发条件

满足任一条件时，本文适用。

1. 用户希望不打开应用就触发一次应用动作。
2. 用户希望从主屏直接进入应用的某个工作区。
3. 用户希望用硬件按钮触发应用动作。
4. 用户希望用系统手势触发应用动作。
5. 用户希望入口在应用未启动时也能工作。

### 1.4 问题分类

| 类别 | 表现 | 主要因素 | 推荐路径 |
| --- | --- | --- | --- |
| 主屏手势 | 需求要求上滑带出面板 | 系统不开放主屏手势 | 改用主屏小组件或快捷指令书签 |
| 锁屏手势 | 需求要求锁屏滑动进入 | 系统不开放锁屏手势 | 改用锁屏小组件或锁屏控件 |
| 边缘手势 | 需求要求边缘滑动进入 | 系统手势属于系统行为 | 不采用 |
| 控制中心 | 希望一键进入指定工作区 | 需要 iOS 18 和用户手动添加 | `ControlWidgetButton` 配 `OpenIntent` |
| 小组件交互 | 希望不打开应用执行动作 | 只支持 `Button` 和 `Toggle`，锁定状态不生效 | 主屏小组件加 App Intent |
| 硬件按钮 | 希望物理按键触发 | 机型受限，需要长按 | Action Button 配 App Shortcut |
| 辅助功能手势 | 希望轻点背面触发 | 属于辅助功能，延迟未知 | 轻点背面加快捷指令 |
| 应用内面板 | 希望保留上滑手感 | 需要应用已在前台 | `presentationDetents` |

### 1.6 解决路径

第一条路径是系统空间入口。
入口包括主屏小组件、锁屏小组件、控制中心控件和 Action Button。
第二条路径是辅助功能手势入口。
入口是轻点背面加快捷指令。
第三条路径是应用内入口。
入口是 `presentationDetents` bottom sheet。
本推荐路径以第一条路径为主，第二条路径为辅。
第三条路径只作为应用内体验，不作为免打开入口。

## 2. 场景定义

### 2.1 主屏快速唤起

用户在 iOS 主屏停留。
用户希望不打开应用就带出一个面板。
此场景是产品需求的原始场景。
此场景决定替代入口的选择。

### 2.2 锁屏快速唤起

设备处于锁屏状态。
用户希望在不进入主屏的情况下触发动作。
此场景受设备认证约束。

### 2.3 应用未启动

应用进程不存在。
用户直接触发入口。
此场景决定入口是否支持冷启动。

### 2.4 首次配置

用户刚安装应用。
用户还没有配置任何入口。
此场景决定每个入口的配置成本。

### 2.5 系统版本不足

设备系统版本低于入口要求。
此场景决定降级路径。

## 3. 成功标准

1. 每个候选入口都有明确的可用性结论。
2. 每个结论标注所需 iOS 版本。
3. 每个结论标注是否需要用户手动配置。
4. 每个结论标注能否在应用未启动时工作。
5. “主屏上滑手势不可实现”有明确证据。
6. 结论给出推荐入口的优先级顺序。
7. 不可实现的入口有明确说明。
8. 每个结论有证据编号。
9. 已知缺口单独列出。
10. 结论不预设实现。
