# 调研方法与技术分析

> 本文件承载调研方法、系统模型、接入面矩阵、约束模型、目标产品分析和方案对比。

## 1. 调研方法

调研分两路执行。

1. 接口路：读取 Apple 接口参考页，提取平台可用性和接口定义。
2. 说明路：读取 Apple 使用手册、支持文章、Human Interface Guidelines 和 WWDC 讲稿。

接口参考页通过 Apple 文档站的数据接口读取。
数据接口返回 JSON，含平台版本表和正文。
WWDC 讲稿页为服务端渲染页，可直接读取正文。
使用手册的正文由浏览器脚本渲染，本次只读取到搜索摘要。

本调研没有 iOS 真机实验。
本机是 macOS，仓库没有 iOS 工程目标。
每一格结论都带证据编号。
证据编号指向 [evidence.md](evidence.md)。

## 3. 系统模型

### 3.1 参与者

| 参与者 | 说明 | 关键属性 |
| --- | --- | --- |
| 设备所有者 | iPhone 用户 | 决定是否添加入口，决定是否解锁 |
| 应用本体 | Covio iOS 应用 | 前台或后台状态，是否已启动 |
| Widget 扩展 | 小组件与控件的宿主进程 | 由系统按需启动，与主应用分离 |
| 系统空间 | 主屏、锁屏、控制中心、Action Button | 决定入口的可见位置 |
| 系统调度 | WidgetKit 与 App Intents 运行时 | 解析入口，执行 App Intent |
| 辅助功能子系统 | 轻点背面 | 把物理手势转成快捷指令 |

### 3.2 组件

| 组件 | 职责 | 出现位置 |
| --- | --- | --- |
| 小组件视图 | 展示状态并承载 `Button` 与 `Toggle` | 主屏、锁屏、StandBy |
| 控件视图 | 展示符号、标题和状态 | 控制中心、锁屏、Action Button |
| App Intent | 描述一个可执行动作 | 主应用与 Widget 扩展 |
| App Shortcut | 把 App Intent 暴露给 Shortcuts 与 Siri | 主应用 |
| 场景路由器 | 把入口请求定位到应用的某个界面 | 主应用 |
| 共享容器 | 在主应用与扩展之间共享状态 | 主应用与 Widget 扩展 |

### 3.3 生命周期

```text
安装 -> 用户添加入口 -> 用户触发入口 -> 系统解析 App Intent -> 执行 perform() -> 刷新入口 -> 结果呈现
```

### 3.4 状态变化

| 阶段 | 正常 | 异常 |
| --- | --- | --- |
| 安装 | 入口出现在图库 | 系统版本低于门槛，入口不可见 |
| 添加 | 用户把入口放到系统空间 | 用户不添加，入口不可用 |
| 触发 | 系统解析并执行 | 设备锁定，动作被挂起 |
| 执行 | `perform()` 正常返回 | 执行抛错，入口显示过期状态 |
| 刷新 | 时间线或控件重载 | 刷新失败，入口保留旧状态 |
| 呈现 | 动作完成，或应用进入前台 | 应用启动失败 |

## 5. 约束模型

### 5.1 四类约束

| 约束 | 说明 | 影响 |
| --- | --- | --- |
| 开放性约束 | 系统只开放部分空间给第三方应用 | 主屏手势和锁屏手势不可用 |
| 版本约束 | 每个接入面有最低系统版本 | 低版本设备只能降级 |
| 配置约束 | 用户必须手动添加入口 | 首次使用前入口不可见 |
| 状态约束 | 锁定设备上部分入口不生效 | 锁屏场景需要认证 |

### 5.2 控制路径

入口触发有三条走向。

1. 后台执行：系统直接执行 `perform()`，应用不进前台。
2. 前台执行：系统先启动应用并带到前台，再执行 `perform()`。
3. 打开并定位：系统启动应用，并把请求路由到指定场景。

第一条路径对应小组件按钮和控件按钮。
第二条路径对应 `openAppWhenRun` 或 `supportedModes` 的前台模式。
第三条路径对应 `OpenIntent` 或 `widgetURL`。

三条路径都要求入口已被用户添加。
三条路径都不要求应用事先运行。

### 5.3 信任边界

| 边界 | 内侧 | 外侧 | 保护手段 |
| --- | --- | --- | --- |
| 设备边界 | 已解锁的设备 | 已锁定的设备 | 系统要求认证后才执行动作 |
| 进程边界 | 主应用 | Widget 扩展 | App Intent 是唯一调用通道 |
| 数据边界 | 共享容器 | 系统空间 | 控件可遮蔽标题与状态 |
| 用户边界 | 已添加的入口 | 未添加的入口 | 用户显式添加与配置 |

## 7. 候选方案对比

| 方案 | 成本 | 风险 | 成熟度 | 可维护性 |
| --- | --- | --- | --- | --- |
| 主屏交互小组件 | 中 | 锁定状态不生效 | 高，iOS 17 起 | 高，与控件共用 App Intent |
| 锁屏交互小组件 | 低，复用小组件代码 | 锁定状态不生效 | 高，iOS 17 起 | 高 |
| 控制中心控件 | 中 | iOS 18 门槛，需要用户添加 | 高，iOS 18 起 | 高 |
| Action Button 放控件 | 低，复用控件代码 | 机型受限 | 高，iOS 18 起 | 高 |
| Action Button 放快捷指令 | 低，复用 App Shortcut | 机型受限 | 高，iOS 17 起 | 高 |
| 轻点背面加快捷指令 | 低 | 延迟未知，属辅助功能 | 中，iOS 14 起 | 中，依赖用户设置 |
| 主屏快捷指令书签 | 低 | 需要用户在 Shortcuts 中操作 | 中 | 中 |
| 主屏上滑手势 | 不可行 | 系统不开放 | 无 | 不适用 |
| 应用内 bottom sheet | 低 | 不是免打开入口 | 高，iOS 16 起 | 高 |

前四个方案共用同一套 App Intent。
因此组合采用的边际成本低。

## 9. 反证和限制

### 9.1 反证

1. 轻点背面的延迟没有官方数据（`E-23`）。
2. 使用手册正文由浏览器脚本渲染，本次只读到搜索摘要。
3. “主屏手势不可用”是负向证据，不是官方否认（`E-02`）。
4. 锁定设备上控件的行为只读到设计指南描述，没有读到执行语义的接口定义。

### 9.2 限制

1. 没有 iOS 真机实验。
2. 没有 B 来源。
3. 没有第三方来源交叉验证。
4. 仓库没有 iOS 工程目标，无法做编译级验证。

## 10. 已知缺口

1. 轻点背面到动作执行的实测延迟。
2. 锁屏小组件按钮在锁定状态下的实际表现。
3. 控制中心控件在锁定设备上的认证语义细节。
4. 各入口在低电量模式下的行为。
5. 各入口在系统重启后第一次触发时的行为。
6. Action Button 在 iPhone 17e 与 iPhone Air 上的可用功能清单。
7. 应用被卸载重装后用户已添加入口的状态。
8. iOS 27 是否新增主屏手势接入面。
