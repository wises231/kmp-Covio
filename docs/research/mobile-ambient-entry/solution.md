# 推荐入口、契约草案与实施条件

> 本文件承载推荐入口顺序、组件职责、契约草案、流程、安全、失败模式、验收和实施条件。

## 1. 推荐方法

### 1.1 路径选择

推荐“一套 App Intent，多个系统空间入口”的方法。
一套 App Intent 指把应用的免打开动作定义成 App Intent。
多个系统空间入口指把同一套 App Intent 接到小组件、控件、Action Button 和 Shortcuts。
选择原因见 [conclusion.md](conclusion.md) 第 4 节。
本文只定义能力边界和契约草案。
本文不排实现任务。
实现留给后续单独评审。

### 1.2 组件

| 组件 | 职责 | 环境 | 启动方式 |
| --- | --- | --- | --- |
| 意图定义 | 描述免打开动作与参数 | 主应用与 Widget 扩展 | 编译期生成元数据 |
| 意图执行器 | 执行动作并返回结果 | Widget 扩展或主应用进程 | 系统按需调用 |
| 快捷指令提供者 | 把意图暴露给 Shortcuts 与 Siri | 主应用 | 随应用安装注册 |
| 主屏小组件 | 展示状态并承载 `Button` 与 `Toggle` | 主屏、Today View | 系统按需渲染 |
| 锁屏小组件 | 展示状态并承载 `Button` 与 `Toggle` | 锁屏 | 系统按需渲染 |
| 控制中心控件 | 执行动作或打开应用 | 控制中心、锁屏、Action Button | 系统按需渲染 |
| 场景路由器 | 把打开请求定位到指定工作区 | 主应用 | 应用启动时 |
| 共享容器 | 在主应用与扩展之间共享状态 | 主应用与 Widget 扩展 | 应用启动时 |

### 1.3 调用路径

```text
用户触发入口（小组件按钮 / 控件 / Action Button / 轻点背面 / 快捷指令书签）
  -> 系统解析入口绑定的 App Intent
  -> 若为后台模式：在 Widget 扩展进程执行 perform()
  -> 若为前台模式：系统启动主应用，在主应用进程执行 perform()
  -> 若为实现 OpenIntent 的意图：系统打开应用并把请求路由到指定场景
  -> 场景路由器按目标参数进入指定工作区
  -> 系统重载入口（时间线或控件）
  -> 入口显示新状态
```

### 1.4 文件位置

本仓库当前没有 iOS 工程目标。
下表是建议位置，待后续单独评审确认。

| 组件 | 建议位置 | 状态 |
| --- | --- | --- |
| 意图定义与执行器 | 待定，共享 Swift 包或主应用目标 | 未创建 |
| 快捷指令提供者 | 主应用目标 | 未创建 |
| Widget 扩展 | 主应用附带扩展目标 | 未创建 |
| 场景路由器 | 主应用目标 | 未创建 |
| 共享容器 | 主应用与扩展共用 | 未创建 |

本仓库当前的 macOS 实现位置不受本调研影响。

## 2. 接口契约草案

本章定义契约草案。
契约草案用于后续评审，不构成实现承诺。

### 2.1 传输

传输方式是 App Intents 框架的进程内调用。
系统解析入口绑定的 App Intent，然后调用其 `perform()` 方法。
主应用与 Widget 扩展之间通过共享容器交换状态。
共享容器是文件或数据库，不是网络通道。
不建立网络通道。
不建立云端通道。

### 2.2 权限

| 权限 | 触发条件 | 拒绝后果 |
| --- | --- | --- |
| 入口添加 | 用户把小组件或控件放入系统空间 | 入口不可见 |
| 入口配置 | 入口需要选择目标工作区 | 入口使用默认目标或不可用 |
| 设备认证 | 设备处于锁定状态 | 动作被挂起，直到解锁 |
| 快捷指令授权 | 用户把快捷指令绑定到轻点背面或 Action Button | 手势不触发动作 |

系统空间入口不需要额外运行时权限。
动作执行不需要网络权限。

### 2.3 协议与稳定字段

稳定字段指跨版本不改变含义的字段。

| 字段 | 类型 | 稳定 | 说明 |
| --- | --- | --- | --- |
| `action_id` | 字符串 | 是 | 动作的稳定标识，与入口绑定 |
| `workspace_id` | 字符串 | 是 | 目标工作区的稳定标识 |
| `source` | 枚举 | 是 | 触发来源，取值见 2.4 |
| `request_id` | 字符串 | 是 | 一次触发请求的标识 |

### 2.4 请求字段

```json
{"request_id":"req-0001","action_id":"covio.workspace.open","workspace_id":"ws-default","source":"control_center"}
```

`source` 取值固定为 `widget_home`、`widget_lock`、`control_center`、`control_lock`、`action_button`、`back_tap`、`shortcut_bookmark`。

### 2.5 响应字段

```json
{"ok":true,"data":{"opened":true,"workspace_id":"ws-default"},"error_code":null,"error_message":null}
```

### 2.6 操作

| 操作 | 参数 | 返回 | 说明 |
| --- | --- | --- | --- |
| `workspace.open` | `workspace_id` | `opened` | 打开应用并进入指定工作区 |
| `workspace.toggle` | `workspace_id` | `state` | 切换工作区的开关状态 |
| `workspace.status` | 无 | `state` | 读取工作区当前状态 |

`workspace.open` 对应实现 `OpenIntent` 的 App Intent。
`workspace.toggle` 对应实现 `SetValueIntent` 的 App Intent。

### 2.7 错误码

| 错误码 | 触发条件 | 可重试 | 人工处理 |
| --- | --- | --- | --- |
| `device_locked` | 设备锁定，动作被挂起 | 是 | 解锁设备后重试 |
| `entry_not_added` | 用户未添加入口 | 是 | 引导用户添加 |
| `workspace_unknown` | 目标工作区不存在 | 否 | 回落到默认工作区 |
| `intent_execution_failed` | `perform()` 抛错 | 是 | 入口显示过期状态并重试 |
| `shared_container_unavailable` | 共享容器不可读 | 是 | 入口显示占位状态 |
| `os_version_unsupported` | 系统版本低于入口门槛 | 否 | 使用更低版本的入口 |

## 3. 关键流程

### 3.1 主屏小组件执行动作

1. 用户在小组件上点按一个 `Button` 或 `Toggle`。
2. 系统解析按钮绑定的 App Intent。
3. 系统在 Widget 扩展进程中执行 `perform()`。
4. `perform()` 写入共享容器并返回。
5. 系统必定重载小组件时间线。
6. 小组件显示新状态。

设备锁定时第 2 步不执行。
系统要求用户认证并解锁。

### 3.2 控制中心控件打开工作区

1. 用户点按控制中心里的控件。
2. 系统解析控件绑定的 `OpenIntent`。
3. 系统把应用带到前台。
4. 场景路由器读取 `workspace_id` 并进入对应工作区。
5. 系统重载控件。

### 3.3 Action Button 触发

1. 用户长按 Action Button。
2. 系统显示动作提示。
3. 系统执行绑定的 App Shortcut 或控件动作。
4. 若动作声明前台模式，应用进入前台。

### 3.4 轻点背面触发

1. 用户双击或三击设备背面。
2. 辅助功能子系统触发绑定的快捷指令。
3. 快捷指令执行 App Intent。
4. 结果按 App Intent 的前台或后台模式呈现。

### 3.5 失败与重试

1. 设备锁定时动作挂起，解锁后由用户重新触发。
2. `perform()` 抛错时入口显示过期状态。
3. 共享容器不可读时入口显示占位状态。
4. 目标工作区不存在时回落到默认工作区。
5. 系统版本不足时隐藏入口。

## 4. 资源策略

1. 小组件与控件只在系统请求时渲染，不常驻。
2. 不在扩展进程中执行长任务。
3. 长任务用 `LongRunningIntent` 或后台任务声明。
4. 共享容器只在 `perform()` 返回前写入。
5. 入口刷新由系统调度，应用不主动轮询。

## 5. 安全设计

1. 免打开动作只暴露幂等或可确认的动作。
2. 有副作用的动作在锁定设备上要求认证。
3. 控件在锁定设备上遮蔽标题与状态。
4. 共享容器不写入凭据。
5. 日志不记录工作区内容和用户数据。
6. 入口不绕过应用内的授权检查。

## 6. 合规设计

1. 入口只使用公开 API。
2. 不使用私有接口或越狱能力。
3. 不要求与功能无关的权限。
4. 不建立后台常驻进程。
5. 每个入口在首次使用时说明用途。

## 7. 可靠性设计

1. 入口状态以共享容器为准，不以渲染结果为准。
2. `perform()` 返回前完成状态写入。
3. 入口刷新失败时保留上一次状态并标记为过期。
4. 目标不存在时回落到默认工作区。
5. 系统版本不足时隐藏入口，不显示不可用控件。

## 8. 失败模式

| 失败 | 表现 | 处理 |
| --- | --- | --- |
| 设备锁定 | 按钮无响应 | 提示解锁后重试 |
| 用户未添加入口 | 入口不存在 | 首次启动引导用户添加 |
| 系统版本不足 | 入口不可见 | 提供低版本入口或应用内入口 |
| `perform()` 抛错 | 入口显示旧状态 | 显示过期标记并重试 |
| 共享容器不可读 | 入口显示占位 | 重试并记录 |
| 目标工作区不存在 | 打开到默认界面 | 回落到默认工作区 |
| 动作耗时过长 | 入口长时间不变 | 用 `LongRunningIntent` 并显示进度 |
| 用户移除入口 | 入口消失 | 不报错，不重复引导 |

## 9. 验收标准

1. 每个入口都有明确的可用性、版本门槛、配置成本和冷启动结论。
2. 主屏上滑手势不可实现这一结论有证据编号。
3. 推荐入口有明确的优先级顺序。
4. 每个入口标注是否支持应用未启动时触发。
5. 每个入口标注是否支持进入指定工作区。
6. 每个入口标注锁定状态下的行为。
7. 结论不预设实现。
8. 已知缺口单独列出。

## 10. 实施条件

本仓库的平台范围是 macOS。
本调研不排任何 iOS 实现 issue。
满足以下条件后，再单独评审实现。

1. 本调研通过评审。
2. iOS 工程目标建立。
3. App Intent 契约草案冻结。
4. 真机验证环境就绪。
5. 产品决定支持的最低 iOS 版本。

## 11. 回滚条件

1. 入口导致应用启动时间明显变长时，回滚该入口。
2. 入口在锁定设备上产生数据泄露风险时，立即关闭该入口。
3. 入口的动作语义与产品不一致时，回滚到应用内入口。
4. 系统版本门槛导致大量用户不可用时，改用更低版本的入口。

## 12. 产品化条件

1. 每个入口的说明与降级路径完整。
2. 真机验证通过。
3. 隐私说明与实际行为一致。
4. 最低支持版本已确定。
5. 契约草案已冻结。
