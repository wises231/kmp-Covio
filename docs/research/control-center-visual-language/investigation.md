# 调研方法与技术分析

> 本文件承载调研方法、系统模型、现有能力矩阵、权限模型、产品分析和方案对比。

主题索引见 [README.md](README.md)。问题边界见 [context.md](context.md)。

## 1. 调研方法

调研分四步。

1. 截图取样。截取控制中心打开时的全屏图像，沿指定直线读像素亮度。
2. 几何反算。用直线上的边缘位置反算圆角半径、模块尺寸和缝宽。
3. 接口核对。读 macOS SDK 的 Swift 接口文件，确认 API 的签名与可用版本。
4. 源码核对。读 Covio 仓库的视图代码与设计合同，确认现状与目标之间的差。

取样工具是本机临时脚本，不随仓库分发。
脚本只做一件事：读 PNG 像素，沿一条直线打印亮度，或者打印相邻两点的亮度差。
复核方法见 [evidence.md](evidence.md) 第 8 节。

## 2. 来源范围

| 等级 | 来源 | 用途 |
| --- | --- | --- |
| A | macOS 27.0 SDK 的 `SwiftUICore.swiftinterface` | `glassEffect`、`Glass`、`GlassEffectContainer` 的签名与可用版本 |
| A | macOS 27.0 SDK 的 `SwiftUI.swiftinterface` | `GlassButtonStyle` 等上层封装 |
| B | Covio 仓库分支 `feature/shell-match-preview`，commit `44b5207` | 工作台视图与几何常量的现状 |
| B | Covio 设计合同 `docs/covio-design-contract.json` | 材质与圆角令牌的定义 |
| C | Apple 的 Liquid Glass 设计说明 | 玻璃的设计意图 |
| D | 本机截图采样 | 控制中心的几何与材质实测值 |
| E | 无 | 本主题不使用第三方来源 |

控制中心是系统进程，没有 B 级来源。
它的取值全部是 D 级，只代表本机环境。
高影响结论由 A 级来源（API 可用性）和 B 级来源（仓库现状）支撑。

## 3. 领域模型

参与者和组件如下。

| 组件 | 职责 |
| --- | --- |
| WindowServer | 合成桌面、窗口和玻璃 |
| 控制中心进程 | 画系统模块。实现私有 |
| Covio 面板窗口 | 透明、无边框、非激活的 `NSWindow` |
| SwiftUI 视图树 | 画卡片与顶栏板 |
| `glassEffect` | 由系统绘制的玻璃底材 |
| 设计合同 | 仓库里的令牌定义 |

生命周期：面板窗口常驻，展开时改高度。
视图树每次展开重建内容。
玻璃由 WindowServer 在合成阶段绘制。

约束：第三方拿不到控制中心的视图树。
控制中心的模块取值只能从截图反推。

## 4. 约束模型

1. 系统组件的实现不公开，只能逼近，不能复制。
2. 玻璃的合成发生在 WindowServer，应用层拿不到中间结果。
3. `glassEffect` 要求 macOS 26 及以上。
4. 面板窗口必须透明、无边框，玻璃才有东西可透。
5. 应用外观（深色或浅色）由系统给，玻璃跟随外观。

## 5. 控制路径

```text
用户触发（手势 / 热区 / 快捷键 / 菜单栏胶囊）
  -> NotchShellController 改窗口高度
  -> HubView 重建视图树
  -> 每个卡片套 glassSurface
  -> SwiftUI 提交绘制
  -> WindowServer 取桌面内容做模糊，与卡片填充合成
```

## 6. 信任边界

本主题不引入新的信任边界。

1. 全部绘制在本机完成，没有网络请求。
2. 玻璃要读桌面内容，这一步由 WindowServer 完成，应用拿不到原始像素。
3. 应用不申请屏幕录制权限。
4. 采样脚本只读本机已有的截图文件。

## 7. 现有能力矩阵

| 能力 | 环境 | 用途 | 限制 | 证据 |
| --- | --- | --- | --- | --- |
| `View.glassEffect(_:in:)` | macOS 26.0 及以上 | 画一块系统玻璃 | 无边框透明窗口里能否画出来要实测 | `E-06` |
| `Glass.clear` | macOS 26.0 及以上 | 更淡的玻璃变体 | 几乎不模糊。背后窗口的文字会透上来 | `E-06`、`E-13` |
| `Glass.regular` | macOS 26.0 及以上 | 标准玻璃变体 | 填充比控制中心重 | `E-06`、`E-13` |
| `Glass.tint(_:)` | macOS 26.0 及以上 | 给玻璃着色 | 着色会改变亮度 | `E-06` |
| `GlassEffectContainer` | macOS 26.0 及以上 | 让相邻玻璃合并 | 间距小于容器 spacing 时两块玻璃会合并 | `E-06` |
| `Material`（`.regularMaterial` 等） | macOS 10.15 及以上 | 降级底材 | 与 Liquid Glass 不是同一种合成 | `E-10` |
| `NSVisualEffectView` | macOS 10.14 及以上 | 老的毛玻璃 | 要包一层 `NSViewRepresentable`，外观联动差 | — |
| 自绘模糊 | 任意 | 自己画 | 拿不到桌面像素，做不到 | — |

## 9. 目标产品源码分析

目标产品是 Covio。固定版本是分支 `feature/shell-match-preview`，commit `44b5207`。

| 文件 | 现状 | 证据 |
| --- | --- | --- |
| `macosApp/src/Design/GlassSurface.swift` | 四个底材取值，默认 `.regular`。改动前全仓库零调用 | `E-07`、`E-13` |
| `macosApp/src/Hub/HubComponents.swift` | `MacCard` 用半透明材质填充，套玻璃 | `E-09` |
| `macosApp/src/Hub/Workbench/BentoWidgetCard.swift` | 首页卡片用色值乘透明度，套玻璃 | `E-09` |
| `macosApp/src/Hub/HubView.swift` | 顶栏板套玻璃，内容区没有底板 | `E-11` |
| `macosApp/src/Design/HubMetrics.swift` | `plateGap` 11 点，`tabBarPlateRadius` 23 点 | `E-11` |
| `docs/covio-design-contract.json` | 定义了半透明材质与 60 点模糊，改动前没有组件使用 | `E-08` |
| `macosApp/Covio.xcodeproj/project.pbxproj` | `MACOSX_DEPLOYMENT_TARGET = 26.0` | `E-12` |

## 10. 参考实现分析

参考实现是控制中心。系统进程，只做外部观察。

### 10.1 几何

同一张截图内沿直线取样得到下表。
截图是 3456 × 2234 像素，2 像素每点。

| 项目 | 像素 | 点 | 证据 |
| --- | --- | --- | --- |
| 面板宽度 | 584 | 292 | `E-01` |
| 左列模块宽度 | 281 | 140 | `E-01` |
| 模块高度 | 99 | 49 | `E-01` |
| 模块圆角 | 38.5 | 19 | `E-02` |
| 水平缝 | 23 | 11.5 | `E-03` |
| 垂直缝 | 54 | 27 | `E-03` |

圆角与模块高度的比值是 0.39。
工作台的 `bentoCardRadius` 是 16 点，卡片高 96 点，比值是 0.17。

### 10.2 材质

模块填充的亮度与紧邻桌面相差 −5 到 −25 级，随桌面内容变化。
模块不靠抬高亮度与桌面区分。

模块内部能看到桌面的模糊：壁纸的亮条穿过模块，边缘被抹开。
说明填充是半透明的，下面有模糊。

模块的边是一条 1 到 2 像素的亮线。
亮线外侧有一条更暗的线。
亮线的亮度随桌面内容变化，是镜面反射的效果。

### 10.3 层级

模块之间没有容器底板。
模块与模块之间的像素等于桌面壁纸本身。
面板只有一个整体圆角，内部不再分层。

### 10.4 内容结构

一个内容按钮由三件组成。

| 元素 | 说明 |
| --- | --- |
| 圆形图标 | 直径约 40 点。开启态是白底，关闭态是灰底 |
| 标题 | 一行，白字 |
| 副标题 | 一行，灰字。显示当前值 |

## 11. 反证和限制

1. 控制中心是 D 级来源。上表的取值只代表本机这一张壁纸与这一版系统。
2. 亮度差随壁纸变化。−5 到 −25 是区间，不是定值。
3. 圆角是从边缘位置反算的。反算用二次方程，有两个根，取了大根。小根是 7.5 像素，与观察不符。
4. 玻璃底材的对照实验不成立。四张截图拍摄时间不同，桌面内容有变化，跨截图的亮度不可比。见 `E-10`。
5. `.clear` 变体的对照只做过一次，见 `E-13`。结论是它不模糊，不能用。
   第一版选它是根据 `.regular` 偏重，没有像素级对照。
6. 控制中心的垂直缝 27 点与水平缝 11.5 点不同。工作台只有一种缝，取 11 点。

## 12. 已知缺口

1. `.regular` 在工作台上只在深色壁纸下对照过。浅色外观未测。
2. 没有浅色外观下的控制中心截图。
3. 没有减弱动态效果下的控制中心截图。
4. 没有玻璃底材在无边框透明面板里画不出来的失败样本。
5. 采样脚本没有随仓库分发。复核要自己写等价工具。
6. 控制中心的取值没有跨系统版本的对比。macOS 26 与 macOS 27 的差异未测。
