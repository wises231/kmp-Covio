# 根因、结论与限制

> 本文件承载结论摘要、根因、决策表、限制和不采用方案。

主题索引见 [README.md](README.md)。证据索引见 [evidence.md](evidence.md)。

## 1. 结论摘要

控制中心的内容按钮由四件事定义。

1. 一条 1 到 2 像素的亮边。亮边由系统绘制，不是自绘描边。
2. 一层半透明填充。填充亮度接近紧邻桌面，模块不靠抬高亮度与桌面区分。
3. 没有容器底板。模块之间直接露出桌面。
4. 圆角约等于模块高度的 0.39。

工作台此前三条都不满足。

1. 卡片用不透明的 `token/color/surface` 填充，模糊被盖住。
2. 内容区有一块统一底板。
3. 卡片自绘 1 点描边与投影。

改法是：玻璃下放到每张卡片，填充换成半透明的 `token/color/material-thin`，删掉内容区底板。

## 2. 根因或决策因素

### 2.1 主要因素

**填充不透明。** 卡片用 `token/color/surface`，深色下是 `#2C2C2E`，完全不透明。
玻璃画在填充下面，模糊被填充盖住。
证据：`E-08`、`E-09`。

**玻璃没有接上。** `GlassSurface.swift` 早就写好，但全仓库零调用。
内容区用的是 `.regularMaterial` 加自绘描边和投影。
证据：`E-07`。

### 2.2 次要因素

**层级错了。** 内容区有一块统一底板，与控制中心的结构不同。
控制中心的玻璃属于每个模块，不属于面板。
证据：`E-04`。

**取值来源错了。** 圆角与缝宽来自设计稿，不是从系统实测。
设计稿的圆角比例 0.17 与控制中心的 0.39 差得远。
证据：`E-02`。

**底材偏重。** `.regular` 变体的填充比控制中心重。
证据：`E-06`、`E-10`。

## 3. 决策表

| 决策 | 选择 | 原因 | 备选路径 |
| --- | --- | --- | --- |
| 玻璃底材 | `Glass.clear` | 控制中心的填充接近桌面亮度。`.regular` 更重 | `.regular`，或退回材质 |
| 玻璃位置 | 每张卡片自己一块 | 控制中心没有容器底板，玻璃属于模块 | 内容区一块板 |
| 卡片填充 | `token/color/material-thin` 半透明 | 不透明填充会盖住模糊 | `token/color/surface` |
| 首页卡片填充 | 色值乘 `token/material/opacity/ultra-thin` | 与控制中心的彩色模块一样是透的 | 不透明色值 |
| 卡片描边 | 只留 1 点 `divider` 分隔线，不加投影 | 控制中心的亮边由系统给 | 自绘亮边加投影 |
| 内容区底板 | 删掉 | 控制中心没有 | 保留一块统一板 |
| 缝宽 | 保持 11 点 | 控制中心的水平缝实测约 11.5 点 | — |
| 顶栏板圆角 | 23 点，等于板高的一半 | 胶囊形，与菜单栏胶囊一致 | 与控制中心一样的 0.39 比例 |
| 设计令牌 | 界面取值以实测为准，不再回填合同 | 用户判断令牌已无用 | 按 `#115` 整体删除合同 |

## 4. 逻辑证据链

### 4.1 观察一：控制中心没有容器底板

观察：模块之间的像素等于桌面壁纸本身。
推论：面板只画模块，不画统一背板。
置信度：高
证据：`E-04`

### 4.2 观察二：模块填充接近桌面亮度

观察：模块填充与紧邻桌面相差 −5 到 −25 级。
推论：模块不靠抬高亮度区分。区分靠边。
置信度：中高。亮度差随壁纸变化。
证据：`E-05`

### 4.3 观察三：模块内部有模糊

观察：壁纸的亮条穿过模块，边缘被抹开。
推论：填充半透明，下面有模糊。
置信度：高
证据：`E-05`

### 4.4 观察四：模块的边是一条细亮线

观察：模块边缘有一条 1 到 2 像素的亮线，外侧有一条更暗的线。
推论：边由系统绘制，是镜面反射效果。自绘描边做不出同样的东西。
置信度：中高
证据：`E-02`

### 4.5 观察五：工作台的卡片此前是不透明的

观察：`MacCard` 用 `MacTheme.surface` 填充，`surface` 是 `#2C2C2E`，不透明。
推论：玻璃画在填充下面，模糊被盖住。
置信度：高
证据：`E-09`

### 4.6 观察六：`.regular` 与材质都不是控制中心

观察：`.regular` 的填充比控制中心重。材质系列的亮度与桌面接近，但没有镜面亮边。
推论：`.clear` 是公开 API 里最接近的一档。
置信度：中。对照实验的跨截图部分不成立，见 `E-10`。
证据：`E-06`、`E-10`

## 5. 不采用方案

| 方案 | 不采用的原因 | 风险 |
| --- | --- | --- |
| 内容区保留一块底板 | 与观察一冲突。放底板等于把统一背板加回来 | 玻璃只有一层，卡片之间没有桌面 |
| 卡片继续用不透明填充 | 与观察二、三冲突。模糊被盖住 | 看不出玻璃 |
| `.regular` 作默认 | 填充比控制中心重 | 界面比系统暗 |
| 材质系列作默认 | 没有镜面亮边，只有模糊 | 卡片边缘发闷 |
| 自绘模糊加半透明填充 | 应用拿不到桌面像素 | 做不到 |
| 玻璃加在内容区，不加在卡片 | 与观察一冲突 | 卡片变成底板上的实心色块 |
| 直接删掉设计合同 | 改动面大，与本次界面调整不是一件事 | 影响全部令牌消费方。按 `#115` 单独处理 |

## 6. 系统限制

1. 控制中心的实现不公开。只能逼近，不能复制。
2. `glassEffect` 要求 macOS 26 及以上。更低版本没有这条路。
3. 玻璃的合成在 WindowServer。应用层拿不到中间结果。
4. 玻璃要读桌面内容。面板窗口必须透明、无边框。
5. 玻璃的表现依赖桌面内容。同一份代码在不同壁纸下观感不同。

## 7. 产品限制

1. 布局与功能与控制中心不同。工作台面板宽 960 点，控制中心面板宽 292 点。
2. 控制中心的垂直缝 27 点与水平缝 11.5 点不同。工作台只有一种缝，取 11 点。
3. 首页卡片是彩色卡片，控制中心只有部分模块有颜色。
4. 玻璃底材画不出来时退回材质，观感会变。
