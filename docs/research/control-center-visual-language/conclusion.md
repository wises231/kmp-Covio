# 根因、结论与限制

> 本文件承载结论摘要、根因、决策表、限制和不采用方案。

主题索引见 [README.md](README.md)。证据索引见 [evidence.md](evidence.md)。

## 1. 结论摘要

**控制中心的效果无法复现。** 公开接口与私有接口都试过，都到不了，见 `E-16` 到 `E-22`。
工作台按 Apple 的官方做法落地：底板取系统的语义材质 `.hudWindow`，走 `NSVisualEffectView`。
材质原样使用，不乘不透明度倍率。用户已在真机上确认接受（2026-10-17）。

控制中心的内容按钮由四件事定义。

1. 一层铺满整个面板的模糊底板。模块内部与模块之间的缝都被抹平。
2. 模块叠在底板上，自己不抬亮。模块内只比桌面亮 8 到 26 级，模块缝比桌面**暗** 8 级。
3. 一条 1 到 2 像素的亮边。亮边由系统绘制，不是自绘描边。
4. 圆角约等于模块高度的 0.39。

工作台此前四条都不满足。

1. 卡片用不透明的 `token/color/surface` 填充，模糊被盖住。
2. 卡片在底板上又叠一层近白填充，抬 73 到 102 级。
3. 卡片自绘 1 点描边与投影。
4. 圆角比例是 0.17。

底材换过四次。

1. 第一版取 `Glass.clear`，那一步是错的。`.clear` 几乎不模糊，背后窗口的文字原样透上来，与卡片正文撞在一起。见 `E-13`。
2. 第二版改成 `Glass.regular`，模糊到位，正文压得住。
3. 第三版把玻璃从每张卡片挪到面板级的底板，卡片叠在底板上。这一版才对上控制中心的层级，见 `E-14`。
4. 第四版把底板从 SwiftUI 的 `Material` 换成 `NSVisualEffectView` 的语义材质 `.hudWindow`。这是 Apple 的官方做法：头文件把 `AppearanceBased`、`Light`、`Dark`、`MediumLight`、`UltraDark` 这一组标了废弃，注释是「You should instead choose an appropriate semantic material.」

底板取不到控制中心的重量。控制中心的底板是 `0.95·桌面 + 0.4`，也就是满量程模糊加近零填充。
会模糊的语义材质里，透光最高的是 `.hudWindow` 的 0.25，填充色 200。私有取值与私有底衬层也到不了。
中途试过给材质层乘一个不透明度倍率，那个旋钮让模糊与填充一起退，两个都保不住，已删除。见 `E-17`。

## 2. 根因或决策因素

### 2.1 主要因素

**填充不透明。** 卡片用 `token/color/surface`，深色下是 `#2C2C2E`，完全不透明。
玻璃画在填充下面，模糊被填充盖住。
证据：`E-08`、`E-09`。

**玻璃没有接上。** `GlassSurface.swift` 早就写好，但全仓库零调用。
内容区用的是 `.regularMaterial` 加自绘描边和投影。
证据：`E-07`。

### 2.2 次要因素

**层级错了。** 内容区那块统一底板一开始被删掉了，那是过度纠正。
控制中心的底板存在，只是工作台那块的取值不对。
证据：`E-14`。

**取值来源错了。** 圆角与缝宽来自设计稿，不是从系统实测。
设计稿的圆角比例 0.17 与控制中心的 0.39 差得远。
证据：`E-02`。

**底材选错。** 只比填充重量会选 `.clear`。
决定能不能看清的是模糊，不是填充，而 `.clear` 几乎不模糊。
证据：`E-06`、`E-10`、`E-13`。

**底板的重量取不到。** 模糊与填充由材质一起给出，不能分开设。
控制中心要的是「满量程模糊加近零填充」，语义材质里没有这一档。
证据：`E-16`、`E-17`、`E-18`、`E-21`、`E-22`。

## 3. 决策表

| 决策 | 选择 | 原因 | 备选路径 |
| --- | --- | --- | --- |
| 玻璃位置 | 面板级底板加卡片两层 | 控制中心是底板加模块，见 `E-14` | 每张卡片自己一块 |
| 底板底材 | 系统的语义材质 `.hudWindow`，走 `NSVisualEffectView` | Apple 的官方做法。头文件把「specific look」那一组标了废弃，要求改用语义材质。面板对应 HUD 窗口。它也不带 Liquid Glass 的镜面亮边 | `Glass.regular`，带亮边；`.ultraThinMaterial` |
| 底板填充倍率 | 不设。材质原样使用 | 倍率让模糊与填充一起退，两个都保不住。`.hudWindow` 是语义材质里最透的一档 | 乘 0.1，板与桌面齐平但文字透上来 |
| 顶栏板底材 | `Glass.regular` | 它是独立胶囊，与控制中心的模块同类，保留亮边 | 与底板同材质 |
| 卡片底材 | `Glass.clear` | 叠在底板上，不重复模糊，保留亮边 | 不透明填充 |
| 卡片填充 | 色值乘 `0.1` | 控制中心的模块几乎不加填充 | 字面量 `0.45` |
| 卡片描边 | 不加 | 控制中心的亮边由系统给 | 自绘亮边加投影 |
| 面板外观 | 跟随系统 | 浅色系统下控制中心是浅底板加深色文字 | 固定深色 |
| 缝宽 | 保持 11 点 | 控制中心的水平缝实测约 11.5 点 | — |
| 顶栏板圆角 | 23 点，等于板高的一半 | 胶囊形，与菜单栏胶囊一致 | 与控制中心一样的 0.39 比例 |
| 设计令牌 | 界面取值以实测为准，不再回填合同 | 用户判断令牌已无用 | 按 `#115` 整体删除合同 |

## 4. 逻辑证据链

### 4.1 观察一（已推翻）：控制中心没有容器底板

观察：模块之间的像素等于桌面壁纸本身。
推论：面板只画模块，不画统一背板。
置信度：**作废。**
证据：`E-04` 由官方宣传图的像素扫描得出。`E-14` 用同一次会话内的矩形均亮对照推翻了它。
模块缝比桌面**暗** 8 级，缝里不是桌面，是一层底板。

### 4.1b 观察一改：控制中心有一层铺满面板的底板

观察：模块缝比桌面暗 8 级，模块内只亮 8 到 26 级，面板整片亮 13 级。
展开后相邻亮度差降到 17%。
推论：模糊来自一层铺满面板的底板，模块叠在上面。
置信度：高。同一次会话内比收起态与展开态。
证据：`E-14`、`E-15`

### 4.2 观察二：模块填充接近桌面亮度

观察：模块填充与紧邻桌面相差 −5 到 −25 级。
推论：模块不靠抬高亮度区分。区分靠边。
置信度：中高。亮度差随壁纸变化。
证据：`E-05`

### 4.3 观察三：模块内部有模糊

观察：壁纸的亮条穿过模块，边缘被抹开。
推论：填充半透明，下面有模糊。
置信度：高
证据：`E-05`

### 4.4 观察四：模块的边是一条细亮线

观察：模块边缘有一条 1 到 2 像素的亮线，外侧有一条更暗的线。
推论：边由系统绘制，是镜面反射效果。自绘描边做不出同样的东西。
置信度：中高
证据：`E-02`

### 4.5 观察五：工作台的卡片此前是不透明的

观察：`MacCard` 用 `MacTheme.surface` 填充，`surface` 是 `#2C2C2E`，不透明。
推论：玻璃画在填充下面，模糊被盖住。
置信度：高
证据：`E-09`

### 4.6 观察六：控制中心模糊，`.clear` 不模糊

观察：把面板开在一个有文字的窗口上，逐像素比对开态与关态。
控制中心的模块内部与模块之间的缝都被抹平，壁纸的细节消失。
`.clear` 底材的卡片背后，窗口文字的字形仍然是锐的，只是对比度降低。
顶栏胶囊更明显：菜单栏的百分比数字透过板子，与标签撞在一起。
推论：决定能不能看清的是模糊。`.clear` 缺这一层，不能用。
置信度：高。同一台机器、同一张壁纸、同一次会话内比对。
证据：`E-13`

### 4.7 观察七：底板的重量取不到

观察：控制中心的底板是 `0.95·桌面 + 0.4`，条纹残留 2%。
公开材质里会模糊的透光最高 0.59，填充色都在 200 以上。
手搭的私有 `CABackdropLayer` 是 0.61·桌面 + 55，填充 140，残留 44%。
推论：控制中心要的是「满量程模糊加近零填充」。公开接口与私有接口都没有这一档。
模糊与填充由同一个旋钮定，只能在这条线上选一点。
置信度：高
证据：`E-16`、`E-17`、`E-18`、`E-21`、`E-22`

## 5. 不采用方案

| 方案 | 不采用的原因 | 风险 |
| --- | --- | --- |
| 删掉内容区底板 | 与观察一改冲突。底板存在，只是取值不对 | 卡片之间没有模糊层，文字透上来 |
| 卡片继续用不透明填充 | 与观察二、三冲突。模糊被盖住 | 看不出玻璃 |
| `.clear` 作默认 | 与观察六冲突。`.clear` 不模糊，背后窗口的文字会透上来 | 正文与背景内容撞在一起，读不出来 |
| 底板取 `Glass.regular` | 与控制中心底板对照冲突。`.regular` 带镜面亮边 | 底板边缘发亮，与顶栏板混成一块 |
| 底板填充倍率取小值 | 与观察七冲突。取小值同时把模糊也调低 | 板与桌面齐平，但背后窗口的文字透上来 |
| 走私有接口拿控制中心的底板 | `E-18`、`E-21` 实测都到不了 | 白担私有 API 的上架风险，还拿不到效果 |
| 自绘模糊加半透明填充 | 应用拿不到桌面像素 | 做不到 |
| 直接删掉设计合同 | 改动面大，与本次界面调整不是一件事 | 影响全部令牌消费方。按 `#115` 单独处理 |

## 6. 系统限制

1. 控制中心的实现不公开。只能逼近，不能复制。
2. **这条差距关不掉。** 控制中心的底板要透光 0.95 的底材，公开接口与私有接口都取不到，见 `E-16` 到 `E-22`。
3. `glassEffect` 要求 macOS 26 及以上。更低版本没有这条路。
4. 玻璃的合成在 WindowServer。应用层拿不到中间结果。
5. 玻璃要读桌面内容。面板窗口必须透明、无边框。
6. 玻璃的表现依赖桌面内容。同一份代码在不同壁纸下观感不同。
7. 文字不随底板亮度翻面。系统没给第三方「这块板现在读起来是深还是浅」的公开信号。
8. 系统在浅色外观时，控制中心是浅底板加深色文字。工作台面板跟随系统外观。

## 7. 产品限制

1. 布局与功能与控制中心不同。工作台面板宽 960 点，控制中心面板宽 292 点。
2. 控制中心的垂直缝 27 点与水平缝 11.5 点不同。工作台只有一种缝，取 11 点。
3. 首页卡片是彩色卡片，控制中心只有部分模块有颜色。
4. 玻璃底材画不出来时退回材质，观感会变。
