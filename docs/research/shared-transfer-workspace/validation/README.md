## 2. 验证目标

验证 [conclusion.md](../conclusion.md) 第 3 节的决策是否成立。
验证 [solution.md](../solution.md) 第 9 节的验收标准是否可达。
目标分四项。

1. 确认四个平台各有一个可用的放入入口。
2. 确认本地优先副本在两端一致。
3. 确认配额、过期和删除的行为符合文档。
4. 确认离线与中断场景可以恢复。

## 3. 范围内事项

1. 四个平台的放入入口与授权要求。
2. 条目索引在设备之间的一致性。
3. 内容副本的传输、校验与断点续传。
4. 按需取回。
5. 配额淘汰、过期清理与删除传播。
6. 移动端后台与前台的行为差别。

## 4. 范围外事项

1. 云端中继与账号体系。
2. 跨网段与公网传输。
3. 商店上架审核。
4. 长期性能与电池测量。
5. 厂商定制系统的全覆盖。
6. 大于 2 GB 的单条目测试。

## 6. 成功标准

1. 每个测试有明确的通过或失败判定。
2. 失败项保留错误码与原始输出摘要。
3. 每个结论回填到 [evidence.md](../evidence.md)。
4. 与文档冲突的观察写入反证章节。
5. 临时文件、授权与系统设置全部恢复。

## 7. 前置条件

1. 两台桌面设备，一台 macOS，一台 Windows。
2. 一台 iOS 设备与一台 Android 设备。
3. 四台设备处于同一局域网。
4. 测试构建使用固定签名。
5. 四台设备已完成配对。
6. 接收端所在磁盘保留不少于 20 GB 可用空间。
7. 测试前记录四台设备的系统版本、应用构建号与账户类型。
8. 测试用内容为无敏感信息的样例文件。

## 8. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 复制真实文件 | 内容可能含敏感信息 | 只用样例文件 |
| 写入相册或公共目录 | 污染用户媒体库 | 只写入应用私有目录 |
| 修改配额或系统设置 | 系统状态被改变 | 记录原值，测试后恢复 |
| 传输大文件占满磁盘 | 系统不稳定 | 限制为 2 GB 并在测试后立即删除 |
| 使用公共服务 | 数据离开局域网 | 只在局域网内测试 |
| 删除传播误删用户内容 | 数据丢失 | 测试用独立工作区目录 |

**警告：** 执行前备份测试设备的工作区目录。删除测试会真实删除文件。

## 10. 证据要求

1. 每个测试记录开始时间与结束时间。
2. 每个测试记录系统版本、构建号与账户类型。
3. 每个测试记录使用的命令或界面路径。
4. 每个测试记录观察到的输出摘要。
5. 内容只记录类型、大小与摘要，不记录正文。
6. 每个条目记录 `entry_id` 的前 8 位。
7. 失败项保留错误码与完整错误信息。
8. 与预期不符的观察写入反证。

## 11. 清理步骤

1. 删除工作区目录中的测试条目。
2. 重置测试设备的配对关系。
3. 删除测试期间写入的系统相册或公共目录内容。
4. 恢复测试前的配额与保留期设置。
5. 恢复测试前的授权状态。
6. 记录清理时间与结果。
