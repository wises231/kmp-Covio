# 推荐架构、接口与实施计划

> 本文件承载推荐架构、接口契约、流程、安全、可靠性、失败模式、验收和实施计划。

## 1. 推荐架构

### 1.1 路径选择

推荐推送模型。
推送模型是唯一覆盖四个平台的路径。
拉取模型只保留给桌面常驻对等端。
选择原因见 [conclusion.md](conclusion.md) 第 3 节。

### 1.2 组件

| 组件 | 职责 | 环境 | 启动方式 |
| --- | --- | --- | --- |
| 内容源适配器 | 从剪切板、截图目录、相册或文件取值 | 每台设备 | 随应用启动 |
| 内容监视器 | 发现本机内容变化 | 桌面常驻，移动端前台 | 随应用启动 |
| 发现服务 | 发布与浏览同网段设备 | 每台设备 | 进入 `Devices` 时 |
| 配对管理器 | 建立并保存设备信任 | 每台设备 | 用户发起配对时 |
| 会话通道 | 加密传输与身份校验 | 每台设备 | 配对完成后 |
| 传输队列 | 分块、校验、续传与重试 | 每台设备 | 有任务时 |
| 落地器 | 写入对端剪切板或接收目录 | 接收端 | 收到内容时 |
| 授权管理器 | 探测权限状态并降级 | 每台设备 | 随应用启动 |
| 唤醒服务 | 通知移动端拉取 | 服务端信令 | 有任务且对端离线时 |

唤醒服务只传递信令。
唤醒服务不保存内容。

### 1.3 调用路径

```text
设备 A 复制内容
  -> A 的内容监视器读取
  -> 内容规范化（类型、大小、摘要）
  -> 传输队列
  -> 配对校验与授权校验
  -> 会话通道（TLS 1.3）
  -> 设备 B 接收器
  -> B 落地（写剪切板或存为文件）
  -> B 回执
  -> A 更新任务状态
```

## 2. 接口契约

### 2.1 传输

传输使用 TLS 1.3。
双方使用长期设备密钥做双向认证。
配对后不再需要用户确认。
控制消息使用换行分隔的 JSON。
内容使用独立的数据流。
控制流与数据流使用同一条连接的不同逻辑通道。

发现路径分三层。
第一层是标准 mDNS。
第二层是自定义组播，组地址与端口独立于 mDNS。
第三层是二维码或手动输入地址。
自定义组播在 Windows 上需要显式指定网络接口（`E-38`）。
Windows 入站监听需要预先放行（`E-37`）。
放行失败时改用出站连接建立会话。

### 2.2 请求

```json
{"request_id":"req-0001","op":"content.push","args":{"kind":"clipboard","content_type":"text/plain","size":1024,"sha256":"<hex>","ttl_seconds":86400}}
```

### 2.3 响应

```json
{"ok":true,"data":{"accepted":true,"task_id":"task-0001"},"error_code":null,"error_message":null}
```

### 2.4 操作

| 操作 | 参数 | 返回 | 说明 |
| --- | --- | --- | --- |
| `device.list` | 无 | 设备列表 | 列出已配对设备与在线状态 |
| `pair.begin` | `mode` | `session_id`、`code`、`public_key` | 开始配对 |
| `pair.confirm` | `session_id`、`code` | `trusted` | 确认配对 |
| `pair.revoke` | `peer_id` | `ok` | 撤销设备 |
| `content.announce` | `kind`、`size`、`sha256` | `accepted` | 通知对端有新内容 |
| `content.push` | `kind`、`content_type`、`size`、`sha256` | `task_id` | 推送内容 |
| `content.pull` | `kind`、`since`、`limit` | 内容描述列表 | 仅桌面常驻对等端 |
| `content.fetch` | `item_id` | 内容流 | 取回指定内容 |
| `transfer.chunk` | `task_id`、`offset`、`length` | `received` | 传输分块 |
| `transfer.commit` | `task_id`、`sha256` | `ok` | 提交并校验 |
| `transfer.cancel` | `task_id` | `ok` | 取消任务 |
| `capability.get` | 无 | 能力与权限状态 | 读取对端可用能力 |

### 2.5 错误码

| 错误码 | 触发条件 | 可重试 | 人工处理 |
| --- | --- | --- | --- |
| `local_network_denied` | 本地网络权限被拒 | 否 | 引导到系统设置 |
| `firewall_blocked` | Windows 入站被防火墙阻断 | 是 | 引导管理员放行 |
| `admin_required` | 当前账户无法完成放行 | 否 | 提示使用管理员账户 |
| `foreground_required` | 移动端不在前台 | 是 | 提示用户打开应用 |
| `clipboard_read_denied` | 剪切板读取被系统拒绝 | 否 | 提示用户手动复制 |
| `photos_denied` | 相册授权被拒 | 否 | 提示改用分享面板 |
| `media_denied` | 媒体库授权被拒 | 否 | 提示改用分享面板 |
| `peer_offline` | 对端不可达 | 是 | 排队等待 |
| `pair_code_expired` | 短码超过 120 秒 | 否 | 重新生成短码 |
| `pair_confirm_mismatch` | 确认码不一致 | 否 | 终止配对并提示风险 |
| `payload_too_large` | 内容超过上限 | 否 | 提示用户换用文件传输 |
| `checksum_mismatch` | 校验失败 | 是 | 删除不完整内容后重传 |
| `disk_full` | 接收端空间不足 | 是 | 提示清理空间 |
| `signature_identity_changed` | 应用签名身份变化 | 否 | 提示重新授权 |

## 3. 关键流程

### 3.1 首次配对

1. 发起端调用 `pair.begin`。
2. 发起端显示二维码与 6 位短码。
3. 二维码携带发起端公钥与临时会话标识。
4. 接收端扫描二维码，或输入短码。
5. 接收端用 `pair.confirm` 提交确认码。
6. 双方显示相同的 6 位确认码。
7. 用户确认后双方交换长期设备密钥。
8. 双方保存信任关系与授权范围。

### 3.2 剪切板推送

1. 桌面端内容监视器发现剪切板变化。
2. 授权管理器检查剪切板读取状态。
3. 内容规范化后进入队列。
4. 向已授权设备发送 `content.push`。
5. 接收端校验后写入本机剪切板。
6. 接收端返回回执。

移动端只在前台执行第 1 步。
移动端也可以由分享面板发起同一流程。

### 3.3 截图推送

1. 桌面端目录监视器发现新截图。
2. 用元数据属性确认是截图。
3. 生成缩略图并写入本地 `Screenshots`。
4. 用户选择发送，或按设置自动发送。
5. 接收端保存到接收目录。

移动端走相册读取或分享面板。
相册读取需要媒体库或相册授权。

### 3.4 移动端拉取

1. 桌面端发现对端离线。
2. 桌面端向唤醒服务登记任务。
3. 移动端收到唤醒后回到前台。
4. 移动端调用 `content.pull`。
5. 桌面端返回待取内容列表。
6. 移动端用 `content.fetch` 取回内容。

移动端在主叫方角色发起连接。
因此不需要常驻监听。

### 3.5 失败与重试

1. 传输中断时任务转为暂停。
2. 网络恢复后从断点继续。
3. 校验失败时删除不完整内容并重传。
4. 对端离线时任务最多保留 7 天。
5. 移动端不在前台时任务保留在队列。

## 4. 资源策略

1. 桌面端监视采用事件驱动，剪切板用计数轮询。
2. 轮询间隔不短于 0.5 秒。
3. 移动端不在前台时停止轮询。
4. 传输默认允许 3 个并发任务。
5. 移动端大文件传输要求前台。
6. 唤醒信令只在必要时发送。

## 5. 安全设计

1. 使用 TLS 1.3 与双向认证。
2. 每台设备持有独立长期密钥。
3. 二维码携带公钥，短码只做辅助。
4. 短码限速，失败次数超限后作废。
5. 短码有效期 120 秒。
6. 确认码不一致时立即终止配对。
7. 内容不经过云端，唤醒服务只传信令。
8. 接收默认需要确认。
9. 已配对设备只能访问已授权能力。
10. 撤销设备后删除会话密钥。
11. 日志不记录内容、文件名和路径。
12. 剪切板内容按上限截断，超限只提示。

## 6. 合规设计

1. 首次启动说明本地网络用途。
2. 每个权限在需要时申请，并说明拒绝后果。
3. 匿名事件不包含内容、文件名、路径和网络地址。
4. 不建立账号体系。
5. 不建立云端内容存储。
6. 移动端不申请与功能无关的后台权限。
7. 前台服务只用于用户发起的任务。

## 7. 可靠性设计

1. 内容先落地到临时目录，校验后移动到目标。
2. 校验失败删除不完整文件。
3. 任务状态持久化，重启后恢复。
4. 接收端空间不足时提前拒绝。
5. 发现失败时提供手动输入路径。
6. 权限缺失时降级而不是崩溃。

## 8. 失败模式

| 失败 | 表现 | 处理 |
| --- | --- | --- |
| 本地网络权限被拒 | 连接超时 | 提示到系统设置，保留手动输入 |
| Windows 入站被防火墙阻断 | 对端无法连接 | 提示管理员放行，或改用出站连接 |
| Windows 标准用户无法放行 | 放行步骤失败 | 说明需要管理员账户 |
| Windows 快速启动后无进程 | 对端不可达 | 按离线处理并排队 |
| 移动端被系统冻结 | 对端不可达 | 排队并登记唤醒 |
| 剪切板读取被拒 | 读取返回空 | 降级为手动复制 |
| 相册授权被拒 | 无法列出截图 | 改为分享面板 |
| 签名身份变化 | 授权状态丢失 | 提示重新授权 |
| 短码被猜中 | 出现伪造配对请求 | 确认码不一致时终止 |
| 传输中断 | 任务暂停 | 断点续传 |
| 校验失败 | 接收端内容损坏 | 删除并重传 |
| 截图目标非文件 | 检测不到截图 | 说明系统限制 |

## 9. 验收标准

1. 桌面端剪切板变化能在 1 秒内进入队列。
2. 两台桌面设备之间可以完成剪切板推送。
3. 一对一配对在 30 秒内完成。
4. 短码在 120 秒后失效。
5. 确认码不一致时配对终止。
6. 移动端在前台可以读到本机剪切板。
7. 移动端在后台不尝试读取。
8. 截图目录监视在授权后可用。
9. 相册读取在受限授权下只显示用户选中的内容。
10. 传输中断后可以从断点继续。
11. 权限被拒时界面给出明确原因和下一步。
12. 撤销设备后对端无法再推送。
13. 标准用户账户上给出明确的放行指引。
14. 快速启动后的设备在 30 秒内被标记为离线。

## 11. 回滚条件

1. 本地网络权限导致无法发现设备时，回滚到手动输入路径。
2. 推送频率影响电池时，延长轮询间隔或改为手动触发。
3. 移动端唤醒不可用时，回滚到仅前台手动同步。
4. 协议变更不兼容时，保持旧版本可用并提示升级。
5. 任何阶段出现内容泄露风险时，立即停止该能力的默认开启。

## 12. 产品化条件

1. 四个平台的权限说明与降级路径完整。
2. 两台桌面设备的端到端验证通过。
3. 移动端前台链路验证通过。
4. 隐私说明与实际行为一致。
5. 商店声明材料准备好。
