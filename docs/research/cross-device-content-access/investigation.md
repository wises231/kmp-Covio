# 调研方法与技术分析

> 本文件承载调研方法、系统模型、现有能力矩阵、权限模型、产品分析和方案对比。

## 1. 调研方法

调研分三路并行执行。

1. Apple 平台：接口文档、技术说明 TN3179、支持文章、本机 SDK 头文件与本机实验。
2. Android 与 Windows：官方行为变更页、AOSP 源码、Android CDD、Microsoft Learn 与政策页。
3. 竞品与协议：各产品官方仓库、协议文档、源码清单与标准文本。

本机实验只覆盖 macOS 端。
移动端结论全部来自官方文档。
每一格能力结论都带证据编号。
证据编号指向 [evidence.md](evidence.md)。

## 3. 系统模型

### 3.1 参与者

| 参与者 | 说明 | 关键属性 |
| --- | --- | --- |
| 设备所有者 | 本机用户 | 拥有本机授权与配对列表 |
| 已配对设备 | 对端设备 | 授权范围、在线状态 |
| 应用进程 | Covio 本体 | 前台或后台状态 |
| 系统授权服务 | TCC、本地网络、相册、媒体库 | 授权状态与提示 |
| 内容源 | 剪切板、截图目录、相册、文件系统 | 可读性与读取时机 |

### 3.2 组件

| 组件 | 职责 | 出现位置 |
| --- | --- | --- |
| 内容读取器 | 从内容源取内容 | 每台设备本机 |
| 内容监视器 | 发现内容变化 | 桌面端常驻，移动端前台 |
| 传输通道 | 发内容到对端 | 局域网 |
| 接收器 | 落地对端内容 | 每台设备本机 |
| 配对服务 | 建立信任关系 | 首次配对时 |
| 发现服务 | 找到同网段设备 | 配对与重连时 |

### 3.3 生命周期

```text
安装 -> 授权 -> 发现 -> 配对 -> 建立信任 -> 读取 -> 传输 -> 落地 -> 撤销
```

### 3.4 状态变化

| 阶段 | 正常 | 异常 |
| --- | --- | --- |
| 授权 | 用户全部允许 | 部分允许，能力降级 |
| 发现 | 找到同网段设备 | 找不到，改为手动输入 |
| 配对 | 短码一致 | 短码失效或确认码不一致 |
| 读取 | 读到内容 | 前台限制或权限不足 |
| 传输 | 完成并校验 | 中断、暂停或失败 |
| 落地 | 保存并显示 | 空间不足或校验失败 |

## 4. 约束模型

### 4.1 三类约束

| 约束 | 说明 | 影响 |
| --- | --- | --- |
| 授权约束 | 系统要求用户逐个能力授权 | 拒绝后能力消失，需要降级路径 |
| 会话约束 | 移动端后台不能读内容 | 移动端只能由用户动作触发 |
| 网络约束 | 本地网络访问需要授权与可见性 | 发现和连接可能需要前台 |

### 4.2 控制路径

读取路径有三种走向。

1. 本机直接读取：应用在允许的窗口内读取本机内容。
2. 本机读取后推送：读取成功后立即发起发送。
3. 对端请求后读取：对端发起请求，本机在收到请求时读取。

第三条路径在移动端不成立。
移动端在后台不能读取剪切板，也不能可靠维持监听。
因此第三条路径只适用于桌面常驻对等端。

### 4.3 信任边界

| 边界 | 内侧 | 外侧 | 保护手段 |
| --- | --- | --- | --- |
| 设备边界 | 本机内容 | 已配对设备 | 配对密钥与授权范围 |
| 网络边界 | 局域网 | 其他网络 | 不建立云中继 |
| 用户边界 | 已授权能力 | 未授权能力 | 逐能力授权开关 |
| 进程边界 | 主应用 | 系统服务 | 系统授权服务裁决 |

## 5. 现有能力矩阵

### 5.1 本机读取能力

| 能力 | macOS | Windows | iOS | Android |
| --- | --- | --- | --- | --- |
| 剪切板读取 | 完整 | 完整 | 仅前台且需用户确认 | 仅焦点应用或默认输入法 |
| 剪切板后台读取 | 可用 | 可用 | 不可用 | 不可用 |
| 剪切板变更通知 | 需轮询计数 | 有系统消息 | 无 | 仅对合格应用触发 |
| 最近截图读取 | 需目录访问授权 | 完整 | 需相册授权 | 需媒体库授权 |
| 截图事件通知 | 无公开接口 | 无公开接口 | 仅应用运行时 | 仅自身界面 |
| 文件读取 | 用户选择 | 完整 | 用户选择 | 用户选择 |

矩阵每一格的证据：剪切板见 `E-02`、`E-07`、`E-10`、`E-18`、`E-24`。
截图见 `E-08`、`E-11`、`E-12`、`E-20`、`E-21`、`E-26`。
文件与后台限制见 `E-09`、`E-15`、`E-23`、`E-28`。

### 5.2 平台权限清单

| 平台 | 能力 | 权限或声明 | 拒绝后果 |
| --- | --- | --- | --- |
| macOS | 截图目录读取 | 文件夹访问授权 | 无法监视截图 |
| macOS | 本地网络 | `NSLocalNetworkUsageDescription` | 无法发现设备 |
| macOS | Bonjour | `NSBonjourServices` 列出服务类型 | 浏览失败且不提示 |
| iOS | 本地网络 | 同上 | 出站连接被拒 |
| iOS | 组播 | `com.apple.developer.networking.multicast` | 只能使用已声明的服务类型 |
| iOS | 相册 | 相册授权 | 无法枚举截图 |
| Android | 媒体库 | `READ_MEDIA_IMAGES` 或部分访问 | 无法读取截图 |
| Android | 本地网络 | `ACCESS_LOCAL_NETWORK`，目标 SDK 37 起 | 连接超时 |
| Windows | 防火墙 | 首次监听时授权 | 入站连接被阻断 |

| 平台 | 主要风险 | 严重度 | 证据 |
| --- | --- | --- | --- |

| iOS | 无法常驻接收 | 高 | `E-15` |
| Windows | 标准用户无法为入站监听放行 | 高 | `E-37` |

## 6. 权限模型

### 6.1 授权粒度

移动端按能力授权。
桌面端按文件夹和网络授权。
两端都没有"读取他人设备"这一类授权。
跨设备读取必须先在对端本机取得授权。

### 6.2 授权与产品能力的映射

| 产品能力 | 需要的授权 | 缺少时的处理 |
| --- | --- | --- |
| 剪切板历史 | 无 | 不可用 |
| 剪切板同步 | 对端本机读取授权 | 只保留本机历史 |
| 截图收集 | 目录或相册授权 | 只保留手动导入 |
| 设备发现 | 本地网络授权 | 改为输入短码 |
| 文件互传 | 用户选择文件 | 无 |
| 自动接收 | 无额外授权 | 需要前台或唤醒 |

## 7. 目标产品分析

分析对象是仓库快照，分支 `feature/swiftui-macos`。
版本基线是 `0.5.0`，未发布。

### 7.1 现状

| 项目 | 现状 | 证据 |
| --- | --- | --- |
| 剪切板监视 | 每 0.5 秒轮询 `changeCount` | `E-06` |
| 截图识别 | 目录监视加扩展属性判断 | `E-06` |
| 本地网络 | 没有代码，没有权限声明 | `E-06` |
| 配对 | 只有产品设计，没有实现 | `E-06` |
| 传输 | 只有产品设计，没有实现 | `E-06` |

### 7.2 声明与现实

| 声明 | 调研结论 | 差异 |
| --- | --- | --- |
| iOS 和 Android 的剪切板同步为"前台和允许的后台窗口" | 移动端只有前台可用 | 声明过于乐观 |
| 移动端截图需要"系统分享面板或扩展" | 成立，但相册读取是另一条路径 | 需要补充分级说明 |
| 桌面端剪切板同步"完整" | 当前成立，未来受闸门影响 | 需要增加授权探测 |

## 8. 参考实现分析

| 产品 | 模型 | 发现机制 | 配对 | 对本项目的参考价值 |
| --- | --- | --- | --- | --- |
| LocalSend | 推送加接收确认 | 自定义 UDP 组播加扫描 | 无配对 | 发现降级方案 |
| KDE Connect | 双向推送 | mDNS 加 UDP 广播 | 证书固定加短码 | 配对算法与剪切板限制 |
| Syncthing | 持续文件夹同步 | 广播与组播 | 双方添加设备 ID | 唯一拉取模型 |
| Warpinator | 推送加接收确认 | 标准 mDNS | 组码 | 标准 mDNS 的唯一采用者 |
| 隔空投送与快速分享 | 推送加确认 | 系统私有机制 | 系统身份 | 交互模式参考 |

### 8.1 关键观察

所有参考产品都要求对端有已授权且运行中的应用。
没有产品实现"对端无动作时读取对端内容"。
KDE Connect 的手机到电脑剪切板同步因为 Android 10 的限制而失效。
LocalSend 为避免 mDNS 限制改用自定义组播（`E-30`）。
五款主流局域网应用都不使用 Windows 的 DNS-SD 接口（`E-38`）。
因此自定义发现路径是常规做法，不是例外。

## 9. 候选方案对比

| 方案 | 成本 | 风险 | 成熟度 | 可维护性 |
| --- | --- | --- | --- | --- |
| 推送为主，拉取仅桌面 | 中 | 移动端需用户动作 | 高，有先例 | 高 |
| 全平台拉取 | 高 | 移动端不可实现 | 低 | 低 |
| 持续文件夹同步 | 中 | 资源占用与隐私 | 中，有先例 | 中 |
| 依赖系统原生通道 | 低 | 跨生态不可用 | 高 | 高，但不可控 |
| 云端中继 | 高 | 违反产品约束 | 高 | 中 |
| Wi-Fi Aware 点对点 | 中 | 仅 Apple 生态 | 低，iOS 26 起 | 中 |

推荐第一种方案。
理由是全平台可用、有先例、且不违反产品约束。
第二种方案在移动端被系统限制否决。
第三种方案作为可选增强，不作为默认。

## 10. 反证和限制

### 10.1 反证

1. 本机剪切板实测为 `alwaysAllow`，与接口文档注释不符。
2. Apple Platform Security 与 TN3179 对 MDM 配置本地网络的说法冲突。
3. Doze 状态下的前台服务网络行为，两份官方表格冲突。
4. `ACCESS_LOCAL_NETWORK` 在接口参考中存在，在抓取的 AOSP 清单中未找到。
5. Windows 原生 DNS-SD 有文档，但没有同行采用（`E-28`、`E-38`）。
6. "Android 12 CDD 强制截图路径"的引用来自草案，已撤销（`E-42`）。

### 10.2 限制

1. 本机实验只覆盖 macOS。
2. 没有真机交叉验证。
3. "无公开接口"类结论是负向证据。
4. 三路调研共用搜索配额，部分条目未核实。

## 11. 已知缺口

1. 移动端后台行为的真机验证。
2. 厂商定制系统的截图路径与后台策略。
3. 组播权限的申请周期。
4. 公证应用在 macOS 27 上的剪切板默认行为。
5. Android 17 的实际发布时间表。
6. Windows 标准用户在管理员预先放行后的实际行为（`E-37`）。
7. Windows 服务提升到用户界面的可用性（`E-39`）。
