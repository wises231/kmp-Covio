## 背景

挂帘是常驻的后台界面。触发层会持续监听指针或手势。
组件网格会渲染多个实时视图。
产品总稿 7.6 节有性能目标。现有截图工具条用 10 Hz 轮询
（`ShelfRuntime.swift:130`），这条轮询本身就有成本。

## 目标

设定并验证工作台的性能与资源预算。

## 待设定的预算

1. 挂帘从触发到可见的耗时。
2. 挂帘展开与收起的动画帧率。
3. 空闲状态下的 CPU 占用。
4. 空闲状态下的内存占用。
5. 配置文件的读写耗时。
6. 组件数量上限下的渲染耗时。

## 实施要点

1. 用 Instruments 采集基线：0.5.0 与改造后的对比。
2. 触发监听不引入新的高频轮询。手势与悬停用事件驱动。
3. 组件只在挂帘可见时更新。挂帘收起后停止刷新。
4. 网格渲染使用惰性容器。
5. 配置写入做去抖，避免每次拖动都落盘。
6. 预算写入 `docs/`，附实测数据与机器型号。

## 验收标准

1. 空闲 CPU 占用不高于 0.5.0。
2. 空闲内存占用不高于 0.5.0 加 50 MB。
3. 触发到可见的耗时不超过 280 毫秒。
4. 挂帘收起后组件停止刷新。
5. 拖动组件时配置文件写入次数有上限。
6. 实测数据与机器型号写入文档。
