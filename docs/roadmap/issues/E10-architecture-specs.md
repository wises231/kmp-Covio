## 背景

`docs/design/workbench-architecture.md` 给出了四层的职责、边界和关键类型名。
它只写到结构级：不给函数签名，不给字段清单，不给状态迁移表。
以上三项由 ADR 和实现类 issue 定。

问题出在「由谁定」没有指派到具体 issue。
`E01` 到 `E07` 共 34 个 sub-issue 各自定各自的接口。
四个触发源的签名分散在四条 issue 里。`PREVIEW` 与 `EDITING` 没有统一的迁移表。
`workbench.json` 的字段清单在不同 issue 里写法不一。
骨架里已有的类型名在 issue 正文里出现 0 次：issue 仍在写 `NotchShellController`。

同一条边界还被两份文档分头引用。
`E00-S03`（`ADR-002`）已占用骨架第 8 节的一部分。
`E00-S04`（`ADR-003`）已占用骨架第 4 节的一部分。
不划清边界，同一个问题会被裁两次。

## 目标

1. 四层的接口契约各有唯一权威，写在 `docs/adr/` 下。
2. 骨架第 10 节列出的每条待裁决项都有结论，并能指到一份 ADR 的小节。
3. `E01` 到 `E07` 的正文以骨架和 ADR 为参照，不再自定类型名与文件位置。
4. `ADR-002` 与 `ADR-003` 的边界在受影响的 ADR 正文里写清，两处不重复裁决。
5. 骨架文档自身的内部矛盾全部裁决并回填。

## 范围

范围内：

- 六份 ADR，放在 `docs/adr/`。
- 骨架文档第 10 节回填 ADR 的编号。
- `E01` 到 `E07` 的正文按骨架对齐。

范围外：

- 任何生产代码改动。
- `workbench.json` 的完整路径、版本字段名与升级策略。归 `E00-S03`。
- `CurtainTrigger` 协议的边界、事件形状与去重层。归 `E00-S04`。
- `WorkbenchConfig` 的字段清单。归 `E03-S01`。
- `E00` 系 issue 的正文改动。
- 设计合同与文案同步。归 `E08`。

## 退出条件

1. `ADR-004` 到 `ADR-009` 六份文件存在于 `docs/adr/`，状态均为「已接受」。
2. 骨架第 10 节的每条待裁决项都能指到一份 ADR 的小节。
3. `ADR-004` 正文写明它与 `ADR-003` 的边界，无重复条款。
4. `ADR-008` 正文写明它与 `ADR-002` 的边界，无重复条款。
5. `WidgetCatalog` 的层位已裁决，并回填骨架第 3.1 节与第 7 节两处。
6. 路线图第 9.1 节的 `U-04` 已裁决。`E00-S04` 验收第 3 条按结论改写或保留。

## 依赖

`E00-S03` 与 `E00-S04` 的结论。两条都裁边界。
`E10-S05` 与 `E10-S06` 要在它们之后定稿，其余四条不等待。

## 风险

一条 ADR 拖期会让它约束的那一层无法开工。
缓解：`E10-S01` 与 `E10-S02` 优先，两条分别约束 `E01` 和 `E02`，处在关键路径上。

`E10-S05` 与 `E00-S03` 同源，`E10-S06` 与 `E00-S04` 同源。
同源的两份文档对同一件事表态不一致时，`E00` 系的 ADR 优先。
