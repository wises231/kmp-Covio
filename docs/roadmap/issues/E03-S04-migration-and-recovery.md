## 背景

工作台配置是新增数据。已有用户的 0.5.0 配置里没有这份数据。
配置可能在写入中途损坏，也可能被用户手工改坏。
用户从新版降级回 0.5.0 时，新文件会留在磁盘上。

## 目标

定义首次升级、版本升级、损坏和降级四种情形的行为。

## 实施要点

1. 首次升级：文件不存在时生成默认布局，并写入磁盘。
2. 版本升级：读取 `schemaVersion`，按 `E00-S03` 的规则迁移。
3. 损坏：解析失败时把原文件改名为 `<name>.corrupt-<时间戳>`，再写入默认布局。
4. 降级：新文件保留不动。0.5.0 不认识该文件，忽略即可。
5. 部分损坏：单条工作区记录非法时只丢弃该条，不丢弃整个文件。
6. 迁移必须是幂等的，重复运行结果相同。

## 验收标准

1. 删除配置文件后启动，生成默认布局并落盘。
2. 写入非法 JSON 后启动，应用能启动，且保留 `.corrupt-` 副本。
3. 写入未来版本的 `schemaVersion` 后启动，行为明确且有测试。
4. 单条非法记录被丢弃，其余记录保留。
5. 迁移重复运行结果相同。
6. `ConfigCompatibilityTests.swift` 的 15 条用例继续通过。
